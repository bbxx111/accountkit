## 行为证据

- 手机/邮箱换绑均保持 user_id、生成新身份 ID，并在事务中软删除旧身份及撤销其他会话；软删除历史行和失败回滚由领域数据库测试直接检查。
- 验证 scope、新鲜度、账户/会话状态、归属、同目标/跨类型、同类上限、多版本摘要和新密钥写入；无效预检不消费验证码，事务内竞争或回滚不恢复已消费码。
- PostgreSQL 触发器、行锁和 `pg_blocking_pids` 编排确定性交错，不使用生产测试钩子或只靠 sleep 推断并发顺序。旧登录/重新认证读取后遇到换绑先提交，会安全拒绝旧证明。
- E2E 验证两个不同设备、必要重新认证、新地址 BIND、200掩码资源、旧路径404、身份列表确认、新地址登录原账号及旧地址自动注册另一个账号；服务额外验证重启及内省。
- 当前会话 refresh/auth_time 连续可用；其他 current/previous refresh（包括宽限重试）受数据库撤销约束。Redis 提交后写失败保持换绑成功并告警，旧 access 保持已有 fail-open 限制。
- 验证成功/拒绝审计、request_id 关联、敏感数据不泄露和管理审计 DTO 的新增枚举；异步审计存储失败不传播的机制由既有审计测试及提交后调用关系共同覆盖，没有声称换绑 E2E 单独注入了审计存储故障。
- “响应丢失后恢复”验证的是旧路径重试404和列表确认协议，不包含网络层丢包故障注入。

## 审查与实施修正

领域、并发防护、HTTP 和 E2E 均经过非作者独立审查，最终整分支审查无遗留实质问题。E2E 审查发现测试缺少显式时间预算，已增加根测试1分钟运行预算、HTTP10秒预算、独立10秒清理预算，以及服务审计查询10秒预算；修正后定向测试、vet及 Linux race 通过。

计划曾误以为管理审计已有事件类型筛选；核对实际接口后修正为枚举解析和现有审计返回值验证，没有新增管理筛选协议。黑盒 E2E 在公共协议确定后与 HTTP 接入并行编写；完成时端点已存在，因此未把依赖配置/冷却错误称为缺失功能 RED，生产行为的红绿证据来自领域、并发和 HTTP 测试。

## 验收边界

按用户要求，实际 SMTP/OIDC 提供方、生产网络/证书和产品环境验收继续暂缓；本地验证不表示在线 CI、部署或发布完成。换绑只继承现有近期认证语义，不承诺每次向旧地址再次发码；账号找回、账号合并和通知系统不在本次范围内。回退不会恢复旧绑定或已撤销会话，具体接入与兼容边界见 [README](../README.md#手机号与邮箱换绑) 和 [兼容说明](compatibility.md#同类身份换绑扩展)。
