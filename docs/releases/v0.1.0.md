## 定位与运行要求

accountkit 是可嵌入宿主的 C 端账号认证 Go 库，module 为 `github.com/bbxx111/accountkit`，根 package 为 `accountkit`。初版面向自有产品接入，包含可选 accountsvc 源码；直接使用库无需部署该服务。此版本的交付范围是 Go 模块及源码，服务二进制或镜像可按[服务手册](../accountsvc.md)自行构建。

- Go：`go.mod` 要求 1.26.5 或更高版本；独立消费支持 `GOWORK=off`。
- 存储：PostgreSQL 与 Redis；当前完整集成验证使用 PostgreSQL 17 和真实 Redis。
- 工具：修改 SQL 查询/映射时使用 sqlc 1.31.1；普通使用方不需要重新生成查询代码。
- 使用范围：当前未附开源 LICENSE，本次发布供自有产品接入，未另行向外部使用方定义复用许可。[许可说明](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository)

v0 系列用于接入反馈和 API 完善，后续版本可能需要源码迁移。已经发布的 tag、SQL 迁移和存储兼容规则仍按项目约定维护，不能因版本为 v0 而改写历史迁移。

## 初版能力

- 手机/邮箱验证码登录、多身份账号、微信/Apple 登录。
- JWT access token、刷新轮换与重试宽限、会话管理、重新认证和身份绑定/解绑/换绑。
- 用户资料、冻结/解冻、注销冷静期、恢复与到期匿名化。
- 独立管理 HTTP 面、角色授权、敏感身份查看与审计。
- 版本化身份加密/摘要、验证码密钥轮换连续性、会话过期检查及维护任务。
- 数据库迁移、历史 SQL 检查、多实例隔离、同事务业务匿名化回调和备份恢复验证。

具体行为和宿主接口见 [README](../../README.md)，功能与兼容对照见[兼容指南](../compatibility.md)。

## 接入方式

### 嵌入库

tag 推送并确认远端可消费后，使用方执行：

```bash
go get github.com/bbxx111/accountkit@v0.1.0
```

Go 导入不包含版本号：

```go
import "github.com/bbxx111/accountkit"
import "github.com/bbxx111/accountkit/httpapi/enduser"
```

宿主沿用 `Config/Deps → New → Migrate → Start → Close` 生命周期，通过 `Auth.EndUserHandler()` 和 `Auth.AdminHandler()` 分别挂载相对路由。直接包装配可使用 `enduser.New` 和 `enduser.Deps`；完整可编译宿主见[嵌入示例](../../examples/embedded/main.go)。

当前旧 `httpapi/consumer` 包与 `Auth.ConsumerHandler()` 已移除；已有源码接入方须按[终端用户入口迁移](../compatibility.md#终端用户-http-入口迁移)调整。根包此前的 `authserver` 名称已改为 `accountkit`，对应说明见[包名迁移](../compatibility.md#包名迁移)。

### 可选 accountsvc

服务入口为 `cmd/accountsvc`，基于同一库提供消费者、管理和内省接口以及探针。单监听器承载 `/v1`、`/admin/v1`、`/v1/introspect`；服务支持明确配置 TLS，链路保护和路由暴露由部署方落实。

- 首版服务提供 SMTP 邮件验证码，短信显式禁用；库宿主仍可注入自己的短信/邮件发送器。
- 管理认证默认关闭，管理接口返回 `503 ADMIN_NOT_CONFIGURED`；启用时配置外部管理员身份提供方。
- 内省使用独立业务客户端凭据；业务服务仍负责自身 scope 和资源归属检查。
- 服务不装配宿主业务匿名化回调；使用此类回调的嵌入式宿主不能与服务混跑同一实例的维护任务。

详细配置和旧部署迁移见[服务手册](../accountsvc.md)与[服务传输迁移](../compatibility.md#服务单监听与传输迁移)。

## 宿主责任与已知运行边界

宿主负责数据库连接池、Redis 客户端、发送器、可信代理/IP、请求 ID、管理员身份验证和业务匿名化回调。不同产品独立配置 schema、Redis 前缀、JWT issuer/audience 和密钥；业务匿名化与账号匿名化使用同一个数据库事务。

验证码流程在 Redis 故障时 fail-closed；刷新宽限查询故障拒绝请求且不误吊销会话；access 吊销查询故障当前 fail-open 并记录警告。内省沿用 access 验证规则，不提供故障时立即拒绝所有旧凭据的保证。审计默认有界异步写入，失败不改变认证动作结果。

入口频率/并发限制、网络隔离、TLS、转发头可信边界与日志保护由宿主或网关落实，依据[网关接入契约](../gateway-integration.md)。Compose、测试 SMTP/OIDC 与代理 fixtures 用于开发和验证，不能代替目标环境验收。
