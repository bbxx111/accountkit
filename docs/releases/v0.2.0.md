# v0.2.0 发布说明

本版本包含验证码轮次协议、宿主账号事务契约与受控离线导入，以及默认 PostgreSQL schema 调整。发布提交、在线 CI 和独立宿主消费证据统一保存在[验收记录](../../openspec/changes/add-host-account-contracts/verification.md)；发布动作完成后更新该记录，已发布 tag 不移动或覆盖。

## 运行与交付范围

- Go module：`github.com/bbxx111/accountkit`，根 package 为 `accountkit`，要求 Go 1.26.5。
- 当前验证环境为 PostgreSQL 17、真实 Redis、sqlc 1.31.1 和 Linux CGO/race；普通使用方无需运行 sqlc。
- 交付 Go 模块与源码，包含可选 `accountsvc`；直接嵌入库无需部署该服务。未发布产品部署、服务镜像或二进制资产。
- 当前未附开源 LICENSE，本版本面向自有产品接入，不额外定义外部复用许可。

## 破坏性升级

### PHONE/EMAIL 验证码轮次

三类发码成功响应由 `{}` 改为 `{code_id, expire_time}`，禁止缓存。PHONE/EMAIL 的登录、绑定、重新认证和换绑凭证都必须携带 `target`、`code_id`、`code`；标识为随机 128 bit 的 32 位小写十六进制，用途由服务器方法确定。旧无标识请求不会回退验证。

Go 调用者同步迁移：三种 `Send*Code` 方法返回 `(user.CodeChallenge, error)`；`SignInWithCode`、`BindWithCode`、`Reauthenticate` 和 `ReplaceIdentity` 改为接收 `user.CodeCredential`。自定义 `enduser.Service`、可选 `IdentityReplacer`、客户端和测试 fake 都须更新。

重发使旧轮次失效，即使数字相同；BIND 绑定用户，REAUTH 绑定用户和会话。过期、未知、已消费及绑定不符的合法标识统一 `CODE_EXPIRED`，不扣新轮次次数。每轮仍默认 5 次，可显式配置为 3 次；最后一次正确可以成功，最后一次错误返回 `CODE_INVALID` 并作废，之后为 `CODE_EXPIRED`。旧 `ErrExhausted` 符号及兼容错误映射保留，但新协议不再产生 `CODE_ATTEMPTS_EXHAUSTED`。

新增跨轮次/用途的目标失败预算，默认首次错误起 15 分钟最多 10 次错误，重发和正确码不清除或延长窗口。第十次错误本身和之后有效请求返回 429 `TARGET_VERIFY_LIMIT` 及剩余 `Retry-After`。新增 `CodeFailureLimitPerTarget`/`CodeFailureWindow`，环境键为宿主前缀加 `CODE_FAILURE_LIMIT_PER_TARGET`/`CODE_FAILURE_WINDOW`；每轮次数、发送额度和冷却配置保持。

### 默认 schema

`v0.1.0` 默认 schema 为 `auth`，本版本默认为 `account`。已有实例继续显式设置 `Config.Schema` 或带宿主前缀的 `AUTH_SCHEMA=auth`，连接池 search_path 与其一致；不要仅升级二进制后依赖新默认值查找旧数据。显式合法 schema 和 Redis 默认前缀 `auth:` 保持。

完整源码/请求迁移对照见[兼容指南](../compatibility.md#验证码轮次契约升级)。

## 新增宿主 Go 契约

- `BatchPublicProfiles(ctx, ids)`：单次批量查询，只返回 ID/DisplayName/State；输入去重，未知略去，待注销/已删除账号清空显示名。宿主先过滤业务权限，无新增资料 HTTP 入口。
- `Deps.BeforeDelete`：消费者/管理员在账号锁及 ACTIVE 检查后、状态改变前使用同一 `pgx.Tx` 调用。明确业务拒绝使用 `ErrDeletionBlocked`，两面固定 400/FAILED_PRECONDITION/DELETION_BLOCKED；其他回调错误固定 500，不解包底层领域哨兵。任一失败回滚账号、会话和同批业务写入。
- `WithActiveUsers(ctx, ids, fn)`：要求非空 ID 集合和非 nil 回调，去重排序锁定全部 ACTIVE 账号再执行同事务业务操作；库提交，error/panic 回滚并释放锁。宿主先锁账号再锁业务资源，不自行结束回调事务。
- `ImportAccounts(ctx, tx, accounts)`：受控停写 Go 工具导入 ACTIVE PHONE/EMAIL 锚点账号或无锚点/名称的 DELETED 墓碑。保留原 ID 和非零原时间，允许历史时钟回退；复用归一化、加密和摘要，冲突失败不合并。调用者负责 schema/批次/引用迁移和最终提交，任何错误后全事务回滚。无导入 HTTP、不发码/建会话/签令牌/访问 IdP。

## 升级与回退

1. 核对原 schema，显式保留已有实例配置；不通过切换默认值迁移数据。
2. 每个账号实例停止旧验证码发码/校验进程，同步 Go 与 HTTP 调用者后启用新协议；无标识旧轮次按原 TTL 淘汰，不清空整个 Redis。
3. 全部进程支持新协议并持有相同完整 HMAC 密钥集合后，才滚动切换 active。轮次、次数、冷却、额度和失败预算保持原期限；相同材料别名不重复计数。
4. HMAC 退役同时等待数据库旧摘要引用归零，以及旧轮次、冷却、UTC 日额度和目标失败预算窗口结束；备份恢复所需历史密钥另行保留。
5. 回退先停止新验证码写/校验，同步调用者并等待新短期状态失效，核对新增错误和状态兼容。不能只回退二进制或清 Redis 宣称安全恢复。

JWT/refresh 协议、身份密文格式、发送器签名、异步审计、冻结迁移及无外键契约保持。宿主仍负责可信代理、入口限流、管理员认证、业务匿名化、网关与实际服务商验收；可选 accountsvc 不替宿主装配业务回调。

## 验证与消费

实施阶段完整本地检查通过：454 个库顶层测试、382 项库必需门禁、66 个服务顶层测试、15 项服务必需门禁及真实恢复三阶段。普通套件唯一 skip 为恢复夹具，该夹具在恢复脚本三阶段实际执行。发布还要求最终 main 候选的在线 CI 成功，随后从实际固定版本完成独立宿主消费。

```bash
go get github.com/bbxx111/accountkit@v0.2.0
```
