# v0.3.0 发布说明

状态：已发布（2026-10-19，北京时间）。[v0.3.0](https://github.com/bbxx111/accountkit/releases/tag/v0.3.0) 固定到 `ba2d0412764c659beabdbd0d3f0f0f9bb9007657`；[最终候选 CI](https://github.com/bbxx111/accountkit/actions/runs/39203841497) 全部成功。两个独立宿主已从远端无 replace 消费 v0.3.0，根门面与直接 enduser 构建及本地装配检查通过，实际证据见[本次验收记录](../../openspec/changes/archive/2026-10-20-prepare-v0-3-0-release/verification.md)。

本版本包含身份策略与登录补全、UUIDv7 通用审计、可定制验证码邮件、标准化指标及 accountsvc 的可选 Prometheus 端点，并补齐 Go 集成指南和两套 HTTP OpenAPI 文档。

## 升级前必须确认

**本版本不能直接接管 v0.2.0 的旧数据库。** 当前初始迁移仍为 version=1，但结构已按此前明确授权整合为包含 `sign_in_completion_flow` 和十列 UUIDv7 审计的基线。版本数字相同不表示结构兼容。

- 旧十七列审计、缺少完整流程结构、仍用 `identity_flow`、新旧流程表并存，以及已撤回的旧 version=2 均拒绝接管，保留原数据、结构和版本。
- 新实例使用经人工核验的新空数据库/schema。已有需要保留的数据必须另行制定和验证迁移方案；本版本不提供旧库自动转换工具。
- 不通过 Force、修改 `schema_migrations`、重复执行初始 SQL 或自动清库绕过校验。公共 `Down` 仍返回 `ErrDestructiveOperation`。
- v0.1.0/v0.2.0 标签与固定源快照保持不变；本次发布准备不再修改初始 SQL。真实后续增量从 0002 开始。

具体操作见[迁移手册](../migrations.md)和[兼容指南](../compatibility.md#初始数据库基线整合)。历史格式和恢复测试证明的是合成数据在当前结构中的兼容性，不是旧库原地升级。

## 新增能力与调用迁移

### 身份策略与登录补全

新增 `EnabledIdentityKinds` 和 `RequiredIdentityKinds`。Required 为 PHONE/EMAIL 的 any-of 条件，省略时默认二选一，显式空列表允许纯第三方账号；显式 Enabled 的子集校验同样适用于 Required 默认值。策略在构造时冻结，不支持热加载。

`SignInWithCode` / `SignInWithIdp` 从 `TokenResult` 改为返回 `SignInResult`，调用者必须处理恰一非空的 `Tokens` 或 `Pending`，同步更新自定义 `enduser.Service`。HTTP 成功令牌字段保持；待补全响应包含 `next_action`、`sign_in_completion_token`、期限和策略集合，不可当作 Bearer 或 refresh token。

新增 `POST /users:sendSignInCompletionCode` 与 `POST /users:completeSignIn`，路径相对于宿主挂载点。网关与客户端须支持两个端点。首次登录提供设备 ID；补全仅接受已启用的 PHONE/EMAIL 证明，并保留设备绑定、票据期限、验证码用途和幂等约束。验证目标属于活动账号时可按规则关联本次未占用身份，已有两个账号不会自动合并。

账号资源继续使用 `/users`、`users/{user_id}` 和 `u_` ID；开发中的 `/accounts` 从未发布，不提供别名。已发布客户端无需改资源名，但须适配新的登录返回分支。纯第三方账号没有手机/邮箱自助恢复路径；近期认证通过普通 IdP 登录取得新 token pair 后，须确认仍为原 user_id。

详见[登录补全兼容说明](../compatibility.md#身份策略与登录补全协议升级)及[Go 集成指南](../go-integration.md)。

### UUIDv7 通用审计

`audit.Event` 改为通用事件模型，`audit.RecordView` 增加存储方首次入库时间；认证输入改用 `audit.AuthenticationEvent` 和 `audit.NewAuthenticationRecorder`。直接生产通用事件的宿主负责 UUIDv7、来源及发生时间，使用 `event.Freeze` 校验和冻结输入。`Inserter.InsertBatch` 改为返回 `BatchResult`，重投递须保留事件 ID 和逻辑事实。

宿主可注入写侧与 `audit.Reader`。注入写侧须明确稳定的 `AuditSource`、`AuditNamespace`；仅写侧模式下，已授权审计查询返回 `503 AUDIT_QUERY_NOT_CONFIGURED`，不回退到本地副本。读侧须遵守资源范围、动作过滤、顺序、分页及流程归属证据契约；库不管理注入组件的生命周期。

审计资源名末段由旧 `e_…` 改为标准 UUIDv7，使用独立 v2 不透明游标。客户端升级后应重新开始审计分页；旧游标不继续使用。其他账号/身份/会话/流程 ID 及 JWT/refresh 格式保持。

业务内容校验集中在 Go，数据库保留结构约束；直接 SQL 导入及修数必须复用应用校验。异步审计仍为尽力记录；外部隐私清理和旧本地副本清理由宿主负责，`USER_PURGED` 不能作为唯一可靠清理通知或完成证据。完整签名、数据边界及迁移对照见[通用审计兼容说明](../compatibility.md#通用审计公开接口与协议迁移)。

### 可定制验证码邮件

正式发送器类型为 `SMSCodeSender`、`EmailCodeSender`、`CodeMessage`；旧 `SMSSender`、`EmailSender`、`Message` 保留 deprecated 别名，原方法签名及依赖字段名保持。

新增 `smtp.NewWithRenderer`，宿主可生成主题、纯文本和可选 HTML；原 `smtp.New` 保留中文兼容渲染。宿主负责语言选择、并发安全、HTML 转义及取消处理。accountsvc 显式采用兼容渲染器；不新增邮件渲染环境变量。见[发送器升级说明](../compatibility.md#验证码发送器命名与渲染接入)和[本地化示例](../../examples/codeemail/renderer.go)。

### 标准化指标与 accountsvc Prometheus

新增可选 `Deps.Observer`，默认及 typed nil 为 no-op。宿主可显式选择 OTel 或原生 Prometheus 适配器，共享有界指标名称、标签、单位与默认直方图桶；不使用请求内容作为动态标签。宿主拥有采集设施、导出和生命周期，适配器依赖纳入同一 Go module。外部结构体字面量使用具名字段，以适应新增依赖字段。

accountsvc 默认关闭指标；通过 `ACCOUNTSVC_METRICS_ENABLED` 和固定非秘密的 `ACCOUNTSVC_METRICS_INSTANCE` 启用同址 `GET /metrics`，无需数据库迁移。部署方须限制监控来源及后端直连，公网不应访问该端点。无观测时可无序列，重启计数重置，停机尾部增量不保证被抓取。

见[指标契约](../metrics.md)和[服务配置](../accountsvc.md#prometheus-指标)。发布准备不代表真实 Prometheus、OTel Collector 或产品网络策略已验收。

### 流程名称与集成文档

内部流程表/模型使用 `sign_in_completion_flow` / `SignInCompletionFlow`。旧公开 `ids.IdentityFlow`、`user.Deps.IdentityFlowContext`、`CleanupIdentityFlows` 保留 deprecated 兼容入口；新上下文字段非空时优先，否则回退旧值。密文 AAD、`f_`、JSON `flow_id` 和审计类型 `IDENTITY_FLOW` 保持。维护任务名称变为 `cleanup_sign_in_completion_flows`，相关日志、指标和告警检索需同步。

新增[Go 集成指南](../go-integration.md)、可编译示例及[两套 HTTP OpenAPI 文档](../openapi.md)。HTTP 前缀仍由宿主挂载，库不监听端口；accountsvc 继续为可选服务。

## 升级与回退顺序

1. 先核对目标数据库结构及数据保留需求，按上述边界选择新空资源或另行验证的数据迁移方案，保留备份和历史密钥。
2. 同步 Go 调用者、客户端、审计适配器和网关补全路由；保留 schema、Redis 前缀、JWT issuer/audience 及实例密钥隔离。
3. 在同一实例内协调所有认证副本与客户端升级后启用身份策略；收紧策略前检查存量可用身份。新登录和新一轮 refresh 可能取得 `user:bind`，已有 access 沿原期限与吊销规则处理。
4. 按需启用邮件渲染和观测设施。只撤销指标功能时可关闭开关/移除 Observer，并移除抓取目标；这不替代整个版本的数据兼容检查。
5. 版本回退前停止新流程、排空在途请求并等待短期状态期限；分别验证旧应用与数据库、协议、配置兼容。旧程序不能直接使用当前基线，不承诺只回退二进制即可恢复。
6. 备份先恢复到独立空库核验；数据库备份不包含 Redis 和密钥系统。不得以清空 Redis、Down 或重建版本标记宣称安全恢复。
