# v0.4.0 发布说明

状态：已发布（2026-10-20，北京时间）。[v0.4.0](https://github.com/bbxx111/accountkit/releases/tag/v0.4.0) 固定到 `62f0799b6c6ef1603b33f81834d39033dd0d0c4d`；[最终候选 CI](https://github.com/bbxx111/accountkit/actions/runs/39408975386) 全部成功。两个独立宿主已从远端无 replace 消费 v0.4.0，根门面与直接 enduser 构建及本地装配检查通过，实际证据见[发布验收](../../openspec/changes/archive/2026-10-20-prepare-v0-4-0-release/verification.md)。

本版本为会话增加必有的认证来源和可选客户端描述：解绑和换绑按来源撤销会话，新增当前会话查询；同时加固内部事务隔离、连接池容量要求、审计分页及身份并发锁序。

## 升级前必须确认

**本版本不能直接接管 v0.3.0 的数据库。** 当前初始迁移仍为 version=1，但已按用户明确授权在未发布的 0001 内纳入会话上下文，共七张业务表。版本数字相同不表示结构兼容。

- 已发布 v0.3.0 的 v1 缺少会话上下文，迁移时返回 `migrations.ErrIncompatibleBaseline`，保留原数据、结构、version 和 dirty。开发期出现过的两种结构同样拒绝：含 known 标记与 INITIAL/LATEST 双快照的 v1，以及已撤回的会话 v2。
- 新实例使用经人工核验的新空数据库/schema。已有需要保留的数据必须另行制定和验证迁移方案；本版本不提供旧库自动转换或来源补造工具。
- 不通过 Force、修改 `schema_migrations`、重复执行初始 SQL 或自动清库绕过校验。公共 `Down` 仍返回 `ErrDestructiveOperation`。
- **v0.3.0 的 Migrate 不检查会话上下文，可能接受本版本创建的同号结构。** 旧程序无法提供本版本的来源校验与撤销规则，部署方须显式阻止新旧副本混跑和未经核验的回退，不能依赖旧迁移器拦截。
- 数据库设计评审调整了 0001 的索引：新增部分唯一索引 `uk_session_user_id_device_id`，作为同设备单一未吊销会话的数据库兜底，并取代 `idx_session_user_id`；调整两个密钥回填复合索引；移除包内无查询使用的 `idx_audit_event_occur_time_id`、`idx_audit_event_request_id`、`idx_audit_event_flow_id` 与 `idx_sign_in_completion_flow_session_id`。宿主或运维若自行按 request_id、flow_id 查询审计表，将不再有对应索引，须自行评估。基线预检不检查索引，开发期已建的同号库不会重放 0001，因此仍保留旧索引，也没有新的唯一兜底。
- v0.1.0/v0.2.0/v0.3.0 标签、已发布 SQL 和固定源快照保持不变，迁移历史检查继续分别固定三代基线。后续结构变更从 0002 开始递增。

具体操作见[迁移手册](../migrations.md#会话认证依据初始整合)及[兼容指南](../compatibility.md#会话认证依据与客户端描述)。恢复演练证明的是合成数据在当前结构中的兼容性，不是旧库原地升级。

## 行为与调用迁移

### 会话认证来源与撤销

- 每个会话必须有一组非空的具体认证身份作为来源，在事务内校验归属和有效状态：普通登录记录本次验证的身份，登录补全记录最终成功验证的全部身份，重新认证用本次手机/邮箱身份整体替换来源并更新 `auth_time`。刷新、普通绑定和换绑的 BIND 证明不改变来源。
- **解绑语义变化**：解绑成功时，在同一事务撤销同账号中来源命中该身份的全部未吊销会话，包括当前会话以及 refresh 已到期但尚未清理的会话。同账号任一未吊销会话缺少有效来源时，整个事务以内部错误拒绝。HTTP 仍返回 204，但当前设备可能随之退出；客户端在后续认证失效时清理凭据并重新登录，不能把成功的解绑重试为失败。
- 解绑撤销的会话使用新增撤销原因 `IDENTITY_UNBOUND`（`enum.RevokeIdentityUnbound`，存储值 9），并为每个被撤销会话记录 `SESSION_REVOKED` 审计。既有枚举值不重编号；审计和会话展示的消费方须能处理新值，回退旧二进制前须确认其对存量值 9 的表现。
- **换绑语义变化**：其他会话仍全部撤销；当前会话仅在有效非空来源不包含被替换身份时保留，命中时一并撤销，来源缺失或失效时回滚。
- 来源缺失或失效是内部不变量错误，返回固定 500，不按“未知”正常处理，也不从身份列表或审计推断。普通 `Authenticate` 与内省仍只做 JWT/Redis 校验，不增加数据库访问；JWT、refresh 和 token 响应格式不变。

### 直接 Go 调用迁移

- 直接 Go 调用 `UnbindIdentity` 现在与 HTTP 一样复核完整 `user` scope、配置要求的近期认证、ACTIVE 账号及数据库中所属的有效当前会话。原来只传 UserID 的调用须改为传入 `Authenticate` 得到的可信完整 `Principal`。HTTP 解绑在会话已吊销或 refresh 已到期时返回 401 `TOKEN_INVALID`，而 v0.3.0 只要 JWT 有效即可成功。`ReplaceIdentity` 在 v0.3.0 已有同等复核，本版本只改变当前会话的保留条件。
- `Meta`、`SessionInfo`、`accountkit.Deps`、`enduser.Deps` 等公开结构新增字段。使用字段名初始化的代码可直接沿用，位置式复合字面量须修改后重新编译。
- **连接池最低容量**：`New` 不做 I/O，直接拒绝 `Deps.Pool.Config().MaxConns < 2`，防止维护任务占满唯一连接。显式设置 `pool_max_conns=1` 或 `MaxConns=1` 的宿主须在升级前改为至少 2；pgx 默认容量不受影响，库也不新建独立连接。
- 库自行开启的领域事务固定使用 READ COMMITTED，`BeforeDelete`、`Anonymizer`、`WithActiveUsers` 回调随之在该隔离级别运行，回调仍须使用传入的同一事务。公开 `Repo.WithTx` / `WithTxRaw` 继续使用宿主默认级别；调用方传给 `ImportAccounts` 的事务不被修改。

### 当前会话查询与客户端描述

- 新增相对路由 `GET /users/me/sessions/current`，允许 `user` 和 `user:bind`，拒绝 `user:undelete`。返回当前会话资源名、数据库中的 `auth_time`、按具体 ID 排序的非空 `authentication_identities`（仅 name/kind）及可选客户端描述，所有响应 no-store。数据库中会话无效时返回 401 `TOKEN_INVALID`，存储依赖故障返回 503 `DEPENDENCY_UNAVAILABLE`，网关不能将其改写为 401。该能力通过可选的 `enduser.CurrentSessionService` 接口提供，不扩大 `enduser.Service`；自定义宿主缺少该能力时返回 503 `SESSION_QUERY_NOT_CONFIGURED`。
- 客户端描述仅在成功的验证码/IdP 登录、补全、重新认证及新一轮刷新时采集，来源依次为显式可选请求头（`X-Client-Type`、`X-Client-OS-*`、`X-Client-Browser-*`、`X-Client-App-*`、`X-Device-Type`、`X-Device-Model`）、Client Hints 和 UA。原 `X-Device-Id` / `X-Device-Name` 及请求体不变，旧客户端照常可用。显式非法值在消费凭证前返回 400 `INVALID_CLIENT_INFO`，token 端点返回 OAuth `invalid_request`。
- 每个会话只保存一份描述：规范化后的非空观察整体替换旧值，nil/空观察保持旧值和时间，失败、回滚和重放不更新。Go `ClientInfo` 保留平坦字段，新增 `DeviceManufacturer`、`AppBuild` 和有界 `Extensions`；存储和 HTTP 采用嵌套 `client_info` 形状，C 端详情及两个面的会话列表提供 `client_info` 与 `client_info_update_time`。`Extensions` 只能来自直接 Go 调用或宿主 `Deps.ClientInfo` 回调，宿主负责其来源、语义和隐私白名单。
- 客户端描述不是可信设备证明，不能用于授权或限流；不保存原始 UA/IP/位置，不进入日志、审计正文或指标标签，随会话清理和匿名化删除。
- 跟随开发分支接入的调用者须删除已移除的 `AuthenticationIdentitiesKnown`、`InitialClientInfo`、`enum.ClientInfoSnapshotKind`（含 INITIAL/LATEST）以及 HTTP 中的 `authentication_identities_known`、`initial_client_info`，并按嵌套形状解析 `client_info`。这些字段从未在已发布版本中出现。

新增公开 API：包 `httpapi/clientinfo`（`Parse` 为 `Deps.ClientInfo` 未设置时的默认解析器）；`enum.ClientType`、`enum.DeviceType`；`user.NormalizeClientInfo`、`user.MergeClientInfo`、`user.ErrInvalidClientInfo`、`user.CurrentSessionInfo`、`user.AuthenticationIdentity` 及 `(*user.Service).GetCurrentSession`；`enduser.CurrentSessionService`。`user/db`、`audit/db` 等 sqlc 生成包的签名有变化，它们不是稳定公共接口，宿主不应直接依赖。

字段边界、扩展限制与示例见 [README](../../README.md#当前会话与客户端描述)、[Go 集成指南](../go-integration.md#当前会话解绑与客户端描述)及 [OpenAPI 说明](../openapi.md)。

### 审计、导入与并发加固

- 本地审计 Reader 按匹配分支取有界候选，只为最终页读取完整事件；`Page.FlowLinks` 仅提供当前页所需的去重流程归属，不能当作账号全部历史流程清单。公开类型、排序、游标、动作范围、source/namespace 及管理面独立复核保持，外部 Reader 契约不变。
- 可能新建手机/邮箱身份的事务（首次登录、补全、绑定、换绑、导入）先对该 subject 的全部摘要版本取事务级 advisory lock，再加行锁，覆盖 HMAC 混合 active 期间的并发。该互斥要求所有进程持有相同的完整密钥集合。
- `ImportAccounts` 先校验并归一化整批输入，再按排序一次性锁定全部 subject，因此输入错误先于任何数据库写入返回；误并行的反序批次排队，后到者得到身份冲突而不是死锁。
- 会话清理跳过正被刷新/吊销事务锁住的行，留待下一轮。建议对认证连接设置 `jit=off`，范围和原因见 [README](../../README.md#数据库与-redis-隔离)。

## 升级与回退顺序

1. 核对目标数据库结构、版本和数据保留需求，选择新空资源或另行验证的迁移方案；保留备份、历史密钥与 Redis 状态。确认连接池 `MaxConns >= 2`。
2. 同步直接 Go 解绑调用、位置式结构体初始化、客户端会话 DTO 和网关路由；网关放行 `GET /users/me/sessions/current`，并按实际使用透传可选客户端头和 CORS。
3. 进入维护窗口，排空旧认证写请求和维护任务，统一切换全部认证副本；不得让旧副本继续创建无来源会话或执行旧的解绑/换绑规则。
4. 用新二进制对核验后的新空目标执行 `Auth.Migrate` 或 `accountsvc migrate`，确认 version=1、dirty=false 及完整七表，再恢复入口；验证解绑 204 后可能退出、客户端重查详情的流程。
5. 回退优先前向修复。应用回退须先停写和排空，另行证明结构、存量来源与安全行为兼容；不能 Down、Force、改版本、自动清库或清空 Redis。
6. 备份先恢复到独立空库，核对两张会话上下文表、每个会话的有效非空来源、单份嵌套客户端 JSON（含 extensions 与原观察时间）、版本及源库未变。数据库备份不包含 Redis 和密钥系统，不承诺零数据损失。

- 模块 `github.com/bbxx111/accountkit`，Go 1.26.5；验证栈为 PostgreSQL 17、Redis 7、sqlc 1.31.1、Linux CGO/race。普通消费者无需 sqlc。本版本新增直接依赖 `github.com/dunglas/httpsfv v1.1.2` 与 `github.com/mileusna/useragent v1.3.5`（用于 Client Hints/UA 解析），`github.com/jackc/puddle/v2 v2.2.2` 由间接依赖改为直接依赖。
- 交付 Go module 和源码，包含可选 accountsvc；不包含服务镜像、二进制或产品部署。当前没有开源 LICENSE，仍面向自有产品接入。
- 完整验证、源码快照、日志、审查及未验证项集中记录于[发布准备验收](../../openspec/changes/archive/2026-10-20-prepare-v0-4-0-release/verification.md)；历史变更记录不能替代最终发布提交的门禁。
- 真实微信/Apple、短信/SMTP、管理员 OIDC、网关、监控平台及目标环境恢复由集成方按[上线清单](../release-checklist.md)验收；任务 8.5 仍未验证。
- 最终 main 候选已通过在线 CI，tag/Release 与固定版本远端消费已核验。使用 `go get github.com/bbxx111/accountkit@v0.4.0` 安装；版本发布不表示产品环境验收完成。
