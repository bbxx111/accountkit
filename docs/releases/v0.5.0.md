# v0.5.0 发布说明

状态：已发布（2026-10-21）。[v0.5.0 Release](https://github.com/bbxx111/accountkit/releases/tag/v0.5.0) 固定到 `102315c3069273f7a8c3ad253c1f4ae01255f8c6`，[最终候选 CI](https://github.com/bbxx111/accountkit/actions/runs/39587858534) 全部通过。安装使用 `go get github.com/bbxx111/accountkit@v0.5.0`；发布、CI、tag/Release 及远端消费证据见[发布验收](../../openspec/changes/archive/2026-10-21-prepare-v0-5-0-release/verification.md)。

本版本在 v0.4.0 之上增加可配置用户资料属性、本人资料 HTTP 及 accountsvc 配置、内置头像地址。模块仍为 `github.com/bbxx111/accountkit`，库可独立嵌入，accountsvc 为可选服务。

## 用户资料属性

- 宿主可配置 `Config.ProfileAttributes` 或 `user.Deps.ProfileAttributes`，值为 `ProfileAttributesConfig{Schema: ...}`；nil 关闭能力。初始化离线编译受支持的 JSON Schema Draft 2020-12 子集，不访问网络或读取文件。
- `GetProfileAttributes` / `PatchProfileAttributes` 提供 Go 读取及部分更新，视图只含 Data，补丁只含 Document。资料保存为单个 `profile_attributes` JSONB，不存 revision、Schema 版本、指纹或独立时间列。
- 内层遵循 RFC 7396：对象递归合并，数组整体替换，null 删除字段，空对象不是清空指令。未知字段（含 null 删除）拒绝，完整结果按当前 Schema 校验；大整数保持精度。修改在账号行锁内合并最新资料，不重叠并发修改保留双方结果，无变化不推进 update_time 或发修改审计。
- 读取允许 ACTIVE/FROZEN，普通修改仅 ACTIVE；冻结和冷静期保留，最终匿名化在原事务清为 `{}`，回调失败整批回滚。成功内容变更通过 `USER_PROFILE_ATTRIBUTES_UPDATED` 尽力审计，只记录固定事实和请求关联，不记录资料内容。
- Schema 上限 64 KiB，补丁及规范化资料分别上限 16 KiB，资料深度 8、值节点 512；具体支持关键字、字段声明、精度及隐私边界见 [README](../../README.md#可选用户资料属性go-与本人-http-接口)。

## 本人 HTTP 与服务配置

- 新增相对 `GET/PATCH /users/me/profile`，要求消费者 `user` scope，无需近期重新认证；目标只来自认证主体，所有响应 `Cache-Control: no-store`。
- PATCH 外层仅接收 `{"profile_attributes":{...}}`，成功返回 200 和完整资料资源。所有已声明资料对本人完整可读写，Schema 的 readOnly/writeOnly 注解不限制权限；启用此能力时不得保存仅供内部访问的属性。
- 消费者必需 `enduser.Service` 方法集保持，通过可选 `enduser.ProfileAttributesService` 接入；能力或 Schema 未配置返回 `503 PROFILE_ATTRIBUTES_NOT_CONFIGURED`。格式错误为 `400 MALFORMED_BODY`，资料语义/Schema 错误为 `400 INVALID_PROFILE_ATTRIBUTES`，状态拒绝沿用 `INVALID_ACCOUNT_STATE`；错误不回显私密输入。
- accountsvc 新增 `ACCOUNTSVC_PROFILE_ATTRIBUTES_SCHEMA_FILE`，仅 serve 在启动前有界读取和校验，migrate 忽略该设置。空配置关闭能力；文件不可读、非普通文件、超限或 Schema 非法阻止启动，运行中不热加载。库 `ConfigFromEnv`/`New` 保持不读文件。

## 头像与基础资料

- 本人资料、管理面用户资源和 Go `BatchPublicProfiles` 新增 `avatar_url` / `AvatarURL`，未设置返回空字符串。待注销/已删除账号的批量公开资料同时隐藏显示名和头像。
- 新增 `user.ProfilePatch` 和 `(*user.Service).UpdateProfile`。`PATCH /users/me` 可同时提交 display_name 和 avatar_url，原子更新；省略或 null 保持，空字符串清空，无有效字段返回 NO_FIELDS。新更新能力在账号锁内复核 ACTIVE。
- 头像 TrimSpace 后最多 2048 字节，要求具有主机的绝对 HTTPS URL；拒绝凭据、fragment、反斜线、内部空白/控制字符及非法 Unicode。库只保存地址，上传、对象存储、可用性及默认头像由宿主提供。头像冻结/冷静期保留，最终匿名化清空。
- `UpdateDisplayName` 保留原签名和行为；可选 `enduser.ProfileUpdater` 不扩大必需 Service。旧自定义适配器仍可修改显示名，含头像而缺能力时返回 `503 PROFILE_UPDATE_NOT_CONFIGURED`，不会部分写入显示名。

## 接入与兼容

本版本以新空 schema 安装为目标，不提供旧库迁移工具。当前 `0001` 已按各次明确授权包含 `profile_attributes JSONB NOT NULL DEFAULT '{}'::jsonb` 和可空 `avatar_url TEXT`，仍为七张业务表、version=1/dirty=false；生产源没有 0002。旧缺列同号结构会无写拒绝，dirty 优先；历史发布 tag/SQL、冻结源分别固定。新实例按 [迁移手册](../migrations.md#当前头像初始定义version-1)装配。

- 旧版认证、token、JWT、内省及身份字段不自动携带 profile_attributes；头像属于明确公开的基础资料。HTTP 严格响应解析器需允许新增 avatar_url。
- Go 公开结构新增字段，使用位置式复合字面量的消费者需改为命名字段。sqlc 生成包不是稳定宿主接口。
- 扩展顶层保留内置字段名，不能重复声明 avatar_url。Schema 配置变化按完整结果校验，移除字段/收紧约束需要宿主处理遗留内容，不自动丢弃资料。
- 开发分支曾有 UserExtensions/Extensions*、expected_revision、Schema 版本/指纹等中间接口；它们未随 v0.4.0 发布。跟随开发提交的调用者按 [兼容说明](../compatibility.md#可选用户资料属性的-go-与-http-接口)调整，固定 v0.4.0 调用者无需迁移这些中间名字。

## 运行与验证

Go 1.26.5、PostgreSQL 17、Redis 7、sqlc 1.31.1。新增直接依赖 `github.com/santhosh-tekuri/jsonschema/v6 v6.0.3`。消费者通常不需要安装 sqlc；两面 OpenAPI 版本为 v0.5.0，消费者 24 个操作、管理面 11 个操作。

交付 Go module 与源码（含可选 accountsvc），不包含服务镜像、二进制或产品部署。当前未附开源 LICENSE，仍面向自有产品。最终候选已通过生成、完整库/服务、race、必需用例及真实恢复门禁。真实微信/Apple、短信/SMTP、管理员 OIDC、网关与目标环境验收仍由集成方按[上线清单](../release-checklist.md)完成。
