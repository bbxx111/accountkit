# v0.6.0 发布说明

状态：已发布（2026-10-24）。tag `v0.6.0`（annotated，对象 `8009c5dcc4622deec6655b1080d254eae41f782d`）固定提交 `ec6802cd221db3ce107e79bac92174bc35a0ba7d`；[最终候选 CI](https://github.com/bbxx111/accountkit/actions/runs/40093942831) 的生成、完整库/服务、race 与真实恢复步骤全部通过，[GitHub Release](https://github.com/bbxx111/accountkit/releases/tag/v0.6.0) 已发布，两个独立宿主已从远端无 replace 消费。证据见[发布验收](../../openspec/changes/prepare-v0-6-0-release/verification.md)。

本版本在 v0.5.0 之上引入身份提供方注册表与统一凭证信封，新增 Google、通用 OIDC、Facebook、支付宝、QQ、微博登录及微信小程序，并把第三方资料补填统一为可配置规则。模块仍为 `github.com/bbxx111/accountkit`，库可独立嵌入，accountsvc 为可选服务。本版本包含破坏性 Go/HTTP 变化和当前初始结构变化，升级前请完整阅读“升级与兼容”。

## 身份提供方注册表与统一凭证

- 所有 C 端身份凭证统一为 `{"kind":"...","credential":{...}}`，覆盖 `signInWithCode`、`signInWithIdp`、`completeSignIn`、`reauthenticate`、绑定与换绑；PHONE/EMAIL 同样使用该信封。各类型 `credential` 内字段沿用原名，发码接口的 `channel`/`target` 不变。
- `enum.IdentityKind` 改为字符串底型，取值即 API 名，零值 `""`；新增 `IsBuiltin()`，`Valid()` 只检查格式 `^[A-Z][A-Z0-9_]{1,31}$`。
- 新增统一接口 `idp.Provider`（`Kind`、`Verify`、`PolicyFingerprint`），内置提供方均实现该接口；`user.Deps.Providers []idp.Provider` 取代原 `WeChat`/`Apple`/`Google` 字段和三个专用验证器接口，`user.IdpCredential` 改为 `{Kind, Credential json.RawMessage}`。
- 注册表在装配时一次性建立、不可变。数据库中存在但当前未注册的类型仍可列出、解绑、匿名化和审计，只是不能用于登录或新绑定。登录补全的配置指纹覆盖全部已注册提供方。

## 新增提供方

| 类型 | 凭证 `credential` | 启用配置 | 说明 |
|---|---|---|---|
| `GOOGLE` | `{id_token, nonce}` | `GoogleClientIDs` / `GOOGLE_CLIENT_IDS` | 以 `sub` 为主键；已验证邮箱仅作 `hint_email` |
| 配置的 OIDC 类型 | `{id_token, nonce}` | `OIDCProviders` / `OIDC_PROVIDERS` 及 `OIDC_<KIND>_*` | 仅 RS256；issuer、JWKS、client ID、nonce 有效期与资料声明名可按类型配置；类型名不得与内置类型重名 |
| `FACEBOOK` | `{id_token, nonce}`（Limited）或 `{access_token}`（Classic） | `FacebookAppID` + `FacebookAppSecret` | 单个 App，App-scoped User ID；Classic 调用 Graph API 并带 `appsecret_proof` |
| `ALIPAY` | `{app_id, code}` | `AlipayApps` / `ALIPAY_APP_IDS` 等 | App 极简授权；RSA2 普通公钥模式；`UNIONID`（默认）/`OPENID` 模式 |
| `QQ` | `{app_id, access_token}` | `QQAppIDs` / `QQ_APP_IDS` | 移动 SDK；`client_id` 须与请求一致；`UNIONID`（默认）/`OPENID` 模式 |
| `WEIBO` | `{app_id, access_token}` | `WeiboAppIDs` / `WEIBO_APP_IDS` | 移动 SDK；`app_id` 即 AppKey；subject 固定 `uid:<uid>` |

- 微信新增小程序：`WeChatMiniProgramApps` / `WECHAT_MINI_PROGRAM_APPS` 通过 jscode2session 验证，与 OAuth 应用共用 `WECHAT` 类型，按服务端 AppID 配置选择流程。新增全局 `WeChatSubjectMode` / `WECHAT_SUBJECT_MODE`（默认 `UNIONID`）。
- 未配置的提供方保持关闭。显式设置 `EnabledIdentityKinds` 的宿主须手动加入新类型；`RequiredIdentityKinds` 仍只接受 PHONE/EMAIL。
- 新增 `Auth.HandleFacebookDataDeletion`、`user.Service.DeleteProviderIdentityData`、`user.ProviderDeletionResult`、`accountkit.ErrFacebookNotConfigured`、`idp.ErrInvalidSignedRequest` 与审计事件 `PROVIDER_DATA_DELETION_PROCESSED`，用于宿主实现 Facebook 数据删除回调：找不到活动身份时幂等返回 `DELETED`；去掉该身份后仍有有效的已启用身份时强制解绑、清空其提供方元数据并吊销以它为认证来源的会话（`DELETED`）；否则发起账号注销进入冷静期（`SCHEDULED`），宿主 `BeforeDelete` 拒绝时返回 `BLOCKED` 且不改动数据。HTTP 回调端点与状态查询页由宿主提供，accountsvc 不提供该回调路由。
- QQ、微博、Facebook Classic 的 access_token 不做一次性限制，有效期内可重复用于登录，客户端须保密令牌。第三方 code、令牌、密钥与原始响应不持久化、不记日志、不进入审计或对外响应。
- 各提供方接入细节见 [支付宝](../alipay-sign-in.md)、[QQ](../qq-sign-in.md)、[微博](../weibo-sign-in.md) 接入指南、[README 配置](../../README.md#配置环境变量前缀由宿主传给-configfromenv) 与 [accountsvc 手册](../accountsvc.md)。

## 第三方资料与显示名

- 提供方返回的 name/picture 声明净化后写入该身份的 `provider_meta.profile`；身份列表与 `:reveal` 不返回 `provider_meta`。头像只接受 HTTPS（QQ 仅对已知头像域名升级 http）。
- 新增 `ProviderProfileBackfill` / `PROVIDER_PROFILE_BACKFILL`，默认 true，所有身份类型规则一致：第三方登录新建账号时始终填充仍为空的显示名与头像；默认开启时，已有账号的第三方登录、绑定与补全关联也只补填空字段，不覆盖非空值；关闭后已有账号不再写入资料。写入在同一事务内锁定账号并复核 ACTIVE 与空值。
- 显示名上限由 32 放宽到 128 个 Unicode 码位，适用于本人更新与第三方填充。

## 指标与审计

- 认证方法追加 `google`、`oidc`、`facebook`、`alipay`、`qq`、`weibo`，宿主登记的其他类型使用固定值 `provider`；依赖操作与降级场景同步追加。类型名、AppID 和秘密不进入标签。
- 审计事件追加 `PROVIDER_DATA_DELETION_PROCESSED`；`IDENTITY_UNBOUND` 与 `USER_DELETED` 现允许 SYSTEM 操作者（数据删除回调产生），按操作者类型过滤审计的读侧需接受该组合。

## 升级与兼容

本版本以新空 schema 安装为目标，不提供旧库迁移工具。完整对照见[兼容说明](../compatibility.md#统一凭证信封与身份类型字符串)及其后各提供方小节。

- **数据库**：当前 0001 按 `add-identity-provider-registry` 与 `add-google-sign-in` 的明确授权调整：`identity.kind` 改为 `VARCHAR(32) COLLATE "C"` 加格式 CHECK `identity_kind_format`，并更新相关注释；无 0002，新安装仍为 version=1/dirty=false。当前 `0001_init.up.sql` SHA256 为 `4c6b565e336aba88db5f6bf219407b026a7c1b438057b61470377005ed2509c5`，与 v0.5.0 的 `491068d7…` 不同。v0.5.0 及更早结构（`identity.kind` 仍为 SMALLINT）无写拒绝，dirty 优先，保留 catalog、数据与 version/dirty；须使用新空资源，不 Force、改版本或清库。见[迁移手册](../migrations.md#当前初始基线)。
- **HTTP 客户端**：v0.5.0 的 `phone`/`email`/`wechat`/`apple` 成员返回 `400 MALFORMED_BODY`，`CREDENTIAL_ONEOF` 不再出现；缺少 `kind`/`credential` 或字段不合法为 `CREDENTIAL_INCOMPLETE`，credential 内的未知字段也由 `MALFORMED_BODY` 改为 `CREDENTIAL_INCOMPLETE`。客户端须与服务端同步升级。
- **Go 宿主**：按数值比较、持久化或构造 `IdentityKind` 的代码改为字符串；改用 `user.Deps.Providers` 装配提供方；`user.IdentityCapabilities` 改为 `{Phone, Email bool; Providers []enum.IdentityKind}`；`ParseIdentityKind` 不再拒绝格式合法的未知类型；显式 `EnabledIdentityKinds` 中的非内置类型必须已登记，否则装配失败。`accountkit.Config` 的既有微信/Apple 字段保留。`idp.Identity` 等公开结构新增字段，位置式复合字面量须改为命名字段。
- **微信 subject**：新 subject 为 `unionid:<unionid>` 或 `openid:<appid>:<openid>`，不匹配历史裸 UnionID；不自动升级、降级、合并或按元数据查找账号。切换模式或应用所属验证组会拒绝已有 pending 流程。
- **进行中的登录补全**：载荷中的类型编码与配置指纹已变化，升级前创建的 pending 流程会被拒绝，客户端须重新开始。
- **资料补填**：默认开启时，GOOGLE/OIDC/FACEBOOK 等提供方在已有账号再次登录时也会补填空字段，用户主动清空的值会在下次第三方登录时重新填充；需要旧的“仅首次”语义的宿主可设为 false，但此时绑定到已有账号也不再填充。
- **显示名**：把 32 个字符写死的宿主需要接受最长 128 个字符。
- **回退**：旧二进制不受支持在新结构上运行：其预检不认识 `identity.kind` 的变化，可能放行新的 version 1，随后在读写身份类型时失败；部署须人工阻止新旧版本混跑和未验证的回退。回退到不认识新类型的版本前，已写入的新类型身份仍可列出、解绑和匿名化，但不能登录；不通过清库或改 subject 回退。

## 运行与验证

Go 1.26.5、PostgreSQL 17、Redis 7、sqlc 1.31.1，无新增或升级的 Go 依赖。两面 OpenAPI 版本为 v0.6.0，消费者 24 个操作、管理面 11 个操作；凭证请求体按统一信封更新。

交付 Go module 与源码（含可选 accountsvc），不包含服务镜像、二进制或产品部署。当前未附开源 LICENSE，仍面向自有产品。Google、OIDC、Facebook、微信小程序、支付宝、QQ、微博均以模拟上游与 HTTP 契约测试验收，未与真实平台、真实 SDK 或真机联调；这些以及短信/SMTP、管理员 OIDC、网关与目标环境验收由集成方按[上线清单](../release-checklist.md)完成。
