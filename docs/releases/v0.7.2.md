## 管理面身份明文响应禁止缓存

- 来源：接入方（ai-food）以真实 Keycloak 验收 v0.7.1 时观察到 `:reveal` 响应没有禁止缓存的头；此前该处理器直接写出 JSON，错误路径的 `apierror` 也不设置 `Cache-Control`。
- 行为：`:reveal` 处理器在入口设置 `Cache-Control: no-store`，其写出的所有响应（200 成功，以及 400 INVALID_ID/INVALID_ARGUMENT、401 TOKEN_MISSING、404 NOT_FOUND、500）一律带该头，由库自身设置，不依赖宿主或网关配置。宿主 verifier 的 401/403、角色中间件的 403 与未配置管理面的 503 ADMIN_NOT_CONFIGURED 在处理器之前产生，不含明文也不带该头，仍由宿主网关策略覆盖。正文仍为既有 `{"name","kind","subject"}`，IDENTITY_REVEALED 审计不变。
- 契约：`docs/openapi/admin.json` 的 `adminRevealIdentity` 200 响应声明 `Cache-Control` 头（`const: no-store`），`scripts/check-openapi.cjs` 断言该声明；规格 `embedded-auth-package`「管理接口及审计兼容」补充要求与场景。其他管理面响应（用户列表/详情、会话、审计）不含明文手机号/邮箱，不在本次范围。
- 宿主责任不变：网关与反向代理不得缓存管理面响应，访问日志仍须对敏感响应做保护；本次只保证库响应自带禁止缓存指令。

## 其他改动

- 测试维护：`internal/accountsvc` 网关集成用例的 `caller_cancel` 变体对已诊断的客户端响应竞争（代理已报 context canceled、上游在打断后才结束、响应为 502 `upstream unavailable`）视为同一网关行为并记录日志；`proxy_exit` 变体与重试检查保持严格。该用例此前已在 CI #43、#102 偶发失败，v0.7.1 发布后的 run [40809097973](https://github.com/bbxx111/accountkit/actions/runs/40809097973) 第一次尝试再次失败（重跑通过）；本次调整只容忍已诊断的竞争，其他结果仍失败，真实依赖下的多次 race 运行记录见[发布准备验收](../../openspec/changes/archive/2026-10-29-prepare-v0-7-2-release/verification.md)。
- 文档：功能清单记录接入方 2026-10-29 的真实 Keycloak 验收结果并收窄待验证项；v0.7.1 发布说明的“运行与验证”同步该事实。
