# v1.1.0

状态：Go 版本已发布（2026-11-15）。保留 `github.com/bbxx111/accountkit` 模块及所有既有导入路径，消费者 `/v1`、管理员 `/admin/v1` 路由保持。accountsvc 与库同源交付，本次不设独立服务版本轴。**相对正式 v1.0.0，accountsvc 的配置与服务授权存在破坏性变化，旧部署必须迁移；公开 Go API 增量兼容不代表全部运行契约兼容。** 本次决定不授权未来任意破坏 v1 契约。

annotated tag `v1.1.0` 对象为 `14b53f3542f8b67a2b42eb5db55eaa8d8bebeaca`，固定提交 `6eef5e349ab17582a5c25b8fa5236372b988a618`；对应 [Go CI](https://github.com/bbxx111/accountkit/actions/runs/43682397743) 和 [SDK CI](https://github.com/bbxx111/accountkit/actions/runs/43682397757) 全部通过，两个独立远端 Go 消费宿主验证成功。[GitHub Release](https://github.com/bbxx111/accountkit/releases/tag/v1.1.0) 使用本说明；发布补记不移动 tag。v1.0.0 历史见[正式发布说明](https://github.com/bbxx111/accountkit/blob/v1.1.0/docs/releases/v1.0.0.md)。

安装：`GOWORK=off go get github.com/bbxx111/accountkit@v1.1.0`。

## 运行要求与新增能力

- Go 1.26.5、PostgreSQL 17、Redis；单一 Go module，支持 `GOWORK=off`，不依赖本地 replace。sqlc 1.31.1 和 PostgreSQL 17 客户端用于仓库验证，运行库无需 sqlc。Go 依赖与生产迁移相对 v1.0.0 未变，冻结的 `0001` 保持，无新生产迁移。
- 新增 `user.ResolveIdentityInput`、`user.ResolvedIdentity` 与 `(*user.Service).ResolveIdentity`。嵌入宿主负责可信 SERVICE 主体及调用授权；根门面不新增透传方法。
- accountsvc 新增 `POST /v1/identities:resolve`，仅以独立 `identities.resolve` 服务权限解析 PHONE/EMAIL 的当前关联，返回最小账号快照；不创建账号、不登录、不签令牌，快照不是后续业务授权证明。请求携带隐私，禁止凭消费者 `/v1/*` 通配公开或记录完整 subject。
- 统一服务客户端注册表为内省、已清理用户拉取、身份解析分配最小权限；新增管理员和服务的 `default` / `rfc9068` token profile，保留两个身份系统的隔离。
- Flutter 与管理 TypeScript SDK 保持已发布的 1.0.0，本轮不发布新 SDK。与 v1.1.0 服务的单元、真实服务、嵌入策略、Git 消费及 Android/iOS 检查均已通过，见上述 SDK CI 与 [SDK 指南](https://github.com/bbxx111/accountkit/blob/v1.1.0/docs/client-sdks.md)。

## 从 v1.0.0 升级：必须核对的变化

| 受影响入口 | 变化及接入要求 |
|---|---|
| accountsvc 旧服务配置 | 移除 `ACCOUNTSVC_INTROSPECTION_BASIC_CLIENTS`、`ACCOUNTSVC_PURGE_FEED_BASIC_CLIENTS`、`ACCOUNTSVC_INTROSPECTION_BEARER_CLIENTS`、`ACCOUNTSVC_PURGE_FEED_BEARER_CLIENTS`。任一非空白值（含 `{}`、`[]`）均在监听前拒绝，空白占位忽略；改用 `ACCOUNTSVC_SERVICE_CLIENTS` 与逐身份字段，不能机械合并旧逐接口同名身份/秘密。migrate 不解析这些服务运行变量。 |
| 注册方法和权限 | 显式声明客户端 ID、方法和权限；三项权限为 `tokens.introspect`、`purged_users.read`、`identities.resolve`，互不隐含。Basic 使用注册权限 P；Bearer 使用 P∩token scope，不自动回退方法。空注册表允许 serve 启动，三能力各自先返回 NOT_CONFIGURED 503。 |
| 服务 Bearer | 必须配置 `BEARER_SUBJECTS` JSON 数组精确绑定专用机器 `sub`，提供方签发所需同名 scope，关闭该主体的人类登录流程。有效令牌缺 scope 为403；错误主体、非法 scope 为401，无宽松兼容开关。提供方禁用客户端不保证旧令牌即时失效。 |
| 新增 token profile | `default` 服务模式仍读取 JWT `azp`；`rfc9068` 读取 `client_id` 并要求标准声明与 `typ`，不互相回退。管理员 profile 独立，不因此取得服务权限或机器主体约束。开发期模式值 `azp` 改名 `default` 未正式发布，不是 v1.0.0 旧配置迁移；JWT `azp` claim 没有改名。 |
| HTTP 凭据边界 | 消费者、管理员和服务入口拒绝重复 Authorization、逗号拼接、多份凭据、TAB/控制字符和尾随空白，校验 token68 形状；scheme 大小写不敏感，允许多个 ASCII 空格。Bearer 上限16 KiB 对消费者为新增边界，管理员/服务原已有上限。自定义 Authenticator 和代理须核对，不能把所有旧输入拒绝笼统视为语法非法。 |
| 错误与挑战 | 有效 Basic 缺端点权限403且无挑战；Bearer缺权限403并带 `insufficient_scope`。401挑战按整个注册表启用方式并集决定，启用 Bearer 且解析可识别单个 Bearer scheme 时，凭据语法/长度拒绝或令牌验证无效的401均带 `invalid_token`，即使未调用 verifier；重复头等无法确定单个 scheme 或客户端未启用该方法时不带该属性。无人持有所需能力优先503，不解析业务正文；完整错误顺序见[服务手册](https://github.com/bbxx111/accountkit/blob/v1.1.0/docs/accountsvc.md#服务调用认证内省与已清理用户拉取)。 |
| OIDC 故障与启动 | 管理员提供方首次不可达不再阻止整个服务启动；服务/管理员密钥在就绪后后台预加载，无可用密钥的认证请求503。整体 `/readyz` 不表达 OIDC 可用性，必须独立验收认证依赖、告警、缓存过期和恢复。 |

升级前盘点四项旧变量、每接口身份/秘密、提供方与网关，保存旧二进制和匹配材料；显式选择同名身份合并或拆分，最小化三权限。转换注册表并删除非空白旧变量；无 Bearer 时移除相关 issuer/audience/profile，有 Bearer 时配置机器主体和 scope，按需选择 profile。联验401/403/503、挑战及三权限隔离，阻断公网与未授权后端直连；最后重启或排空全部副本，配置与权限是启动快照。详细字段和步骤以[服务手册](https://github.com/bbxx111/accountkit/blob/v1.1.0/docs/accountsvc.md#从旧配置迁移与回退)与[兼容指南](https://github.com/bbxx111/accountkit/blob/v1.1.0/docs/compatibility.md#accountsvc-服务客户端配置兼容)为准。

## 成套回退与数据边界

回退须同时恢复支持旧模式的二进制、匹配配置、提供方和调用方凭据及网关策略；旧二进制不认识 `identities.resolve` 等新配置，须恢复其接受的配置，重新准备原独立秘密和不相交 Bearer 名单。当前二进制不能靠取消 `SERVICE_CLIENTS` 恢复旧模式。旧授权语义更宽，回退不是安全等价操作，应重新评估授权范围。

本批无数据库结构升级，不需要清库、清 Redis、Force 或修改 `schema_migrations`；不调用 Down/UnsafeReset。数据库恢复仍先在独立空库核验，备份不涵盖 Redis 和密钥系统，不能承诺零数据损失。长期规则见[迁移手册](https://github.com/bbxx111/accountkit/blob/v1.1.0/docs/migrations.md)。
