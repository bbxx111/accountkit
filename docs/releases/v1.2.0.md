# v1.2.0

状态：发布候选。保留 `github.com/bbxx111/accountkit` 模块及导入路径，消费者 `/v1`、管理员 `/admin/v1` 路由不变。accountsvc 与库同源交付。**相对正式 v1.1.0，accountsvc 管理员授权改为显式角色映射，属于破坏性部署迁移；公开 Go API 加法兼容不表示全部部署兼容。** 本次按明确版本决定使用 v1.2.0，不授权未来任意破坏 v1 契约。

预计安装：`GOWORK=off go get github.com/bbxx111/accountkit@v1.2.0`。正式 tag 将固定包含本候选说明的受测提交，[GitHub Release](https://github.com/bbxx111/accountkit/releases/tag/v1.2.0) 使用同一说明；发布及远端消费通过后以独立补记更新状态和证据，不移动 tag。当前没有宣称最终候选 CI、正式 tag 或远端消费已经通过，实际结果统一见[发布验收记录](https://github.com/bbxx111/accountkit/blob/develop/openspec/changes/prepare-v1-2-release/verification.md)。[v1.1.0 发布说明](https://github.com/bbxx111/accountkit/blob/v1.1.0/docs/releases/v1.1.0.md)保留其历史结论。

## 运行要求与变化

- Go 1.26.5、PostgreSQL 17、Redis；单一 module，支持 `GOWORK=off`，不依赖本地 replace。仓库验证使用 sqlc 1.31.1 和 PostgreSQL 17 客户端，运行库无需 sqlc。
- 新增 `AdminPermission` 别名、十项权限及可选 `AdminPermissionVerifier`。保留 `AdminVerifier.RequireRole` 和既有角色常量；旧嵌入宿主继续按角色工作，实现新接口的验证器优先检查具体权限，拒绝后不回退角色检查。详见[Go 集成指南](https://github.com/bbxx111/accountkit/blob/develop/docs/go-integration.md)。
- accountsvc 移除 operator/super-admin 内置授权与继承，按部署显式映射角色。匹配多个角色时取权限并集；管理员 token scope 不授予、也不收窄管理权限。服务调用权限与管理员权限仍独立。
- 全仓字符串重构保持既有值、路径、JSON/DTO、错误 reason、SQL/schema、JWT/refresh、AAD 与密钥格式。无新生产迁移，无新增运行依赖；pgerrcode 保持同版本，仅由间接改为直接依赖。管理403英文消息由 role 改为 permission；明文 reveal 路由的认证错误也受 `Cache-Control: no-store` 保护，错误 code/reason 和 DTO 不变。
- Flutter 与管理 TypeScript SDK 保持独立 `1.0.0`，本次不创建 SDK 版本或 tag；v1.2.0 兼容验证分别登记在[兼容矩阵](https://github.com/bbxx111/accountkit/blob/develop/sdks/compatibility.json)。历史已验证行不代替本候选证据。

## 从 v1.1.0 升级：必须配置管理员角色

保存旧二进制、配置及提供方角色签发策略。在启用管理员认证的部署中显式设置完整前缀变量，例如保留过去角色名称并按实际职责授予权限：

```dotenv
ACCOUNTSVC_ADMIN_ROLE_BINDINGS=OPERATOR,SUPER_ADMIN
ACCOUNTSVC_ADMIN_ROLE_OPERATOR_NAME=operator
ACCOUNTSVC_ADMIN_ROLE_OPERATOR_PERMISSIONS=users.read,users.freeze,users.unfreeze,sessions.read,sessions.revoke,sessions.revoke_all,audit_events.read
ACCOUNTSVC_ADMIN_ROLE_SUPER_ADMIN_NAME=super-admin
ACCOUNTSVC_ADMIN_ROLE_SUPER_ADMIN_PERMISSIONS=users.read,users.freeze,users.unfreeze,users.delete,users.undelete,identities.reveal,sessions.read,sessions.revoke,sessions.revoke_all,audit_events.read
```

NAME 是 JWT 中的单个精确角色字符串；逗号不会拆分 NAME。别名匹配 `[A-Z][A-Z0-9_]{0,31}`，列表裁剪元素周围空白并拒绝重复/空项，别名及实际角色名分别唯一。PERMISSIONS 为权限 CSV，重复与重叠去重；缺少 NAME/PERMISSIONS、未知权限、未知字段和未声明别名的孤立字段均监听前失败，孤立字段即使空值也拒绝。`ADMIN_AUTHORIZATION_MODE` 从未是正式旧版本配置，不作为 v1.1.0 升级删除项。

11 条管理路由对应 10 项权限（下表省略 `/admin/v1`）：

| 路由 | 权限 |
|---|---|
| `GET /users`、`GET /users/{user}` | `users.read` |
| `POST /users/{user}:freeze` | `users.freeze` |
| `POST /users/{user}:unfreeze` | `users.unfreeze` |
| `DELETE /users/{user}` | `users.delete` |
| `POST /users/{user}:undelete` | `users.undelete` |
| `GET /users/{user}/identities/{identity}:reveal` | `identities.reveal` |
| `GET /users/{user}/sessions` | `sessions.read` |
| `DELETE /users/{user}/sessions/{session}` | `sessions.revoke` |
| `POST /users/{user}/sessions:revokeAll` | `sessions.revoke_all` |
| `GET /users/{user}/auditEvents` | `audit_events.read` |

仅支持资源组通配符 `users.*`、`sessions.*`、`identities.*`、`audit_events.*`，升级会自动包含组内未来操作；固定授权应枚举具体权限。`users.*` 不包含会话、身份或审计，`identities.*` 不授予服务权限 `identities.resolve`，不支持全局 `*`。

空绑定是合法启动配置：管理员认证启用时，有效管理员访问返回403 `ADMIN_FORBIDDEN`；保持旧角色签发而不配置映射也如此。无效凭据仍401，认证依赖故障仍503；未启用管理认证仍503 `ADMIN_NOT_CONFIGURED`。scope 不能补救缺少管理权限。有效旧 token 的精确角色匹配新映射时可以继续使用，无需仅因本迁移强制重新登录。

配置为启动快照；更新或排空全部副本，避免旧副本继续按旧授权运行。角色在提供方撤销不保证已签 JWT 即时失效。逐路由验证预期允许与拒绝、401/403/503、reveal no-store，并独立验收认证依赖和网关。完整配置见[管理员认证](https://github.com/bbxx111/accountkit/blob/develop/docs/accountsvc.md#管理员认证)。v1.1.0 的服务注册表、token profile 和服务 scope 变化已经发布，不重复作为本次新增迁移。

## 成套回退与产品责任

同时恢复旧二进制、匹配配置与角色签发策略，并重新核验权限；旧二进制的 operator/super-admin 内置授权可能恢复更宽权限，回退不是安全等价操作。本次无数据库结构变化，不清库、不清 Redis、不 Force，不调用 Down/UnsafeReset；数据库恢复仍先在独立空库核验，备份不涵盖 Redis 和密钥系统。

准备快照、精确最终 main SHA 的 Go/SDK CI、正式 tag 和两个无 replace 远端 Go 宿主消费须分别留证；缺依赖、skip 或历史结果不能算本次通过。真实 IdP/短信/SMTP、产品网关与部署、监控、升级/恢复和业务匿名化覆盖仍由集成方验收。当前许可边界保持，不新增外部复用许可。
