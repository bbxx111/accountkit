# v1.2.0 发布 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 完成用户已授权的v1.2.0正式发布及独立远端消费，准确保留管理员部署迁移边界。

**Architecture:** 复用现有单Go模块、同源accountsvc和独立SDK版本轴；文档候选、准备快照、最终main、不可变tag及发布后补记分阶段留证。

**Tech Stack:** Go1.26.5、sqlc1.31.1、PostgreSQL17、Redis、现有Docker验证镜像；Node24.21.0/pnpm11.24.0、Flutter3.47.4/Dart3.13.3及Xcode26.1.1。

**Spec:** [OpenSpec设计](../../../openspec/changes/prepare-v1-2-release/design.md)、同目录proposal/tasks和[发布检查表](../../release-checklist.md)。

## Global Constraints

- 本次发布v1.2.0，Go module/import及HTTP路由保持；accountsvc显式管理角色映射为破坏性部署迁移，不称全面向后兼容。
- 不改运行代码、依赖、SQL/冻结哈希、令牌/密文、SDK版本/锁文件，不新增服务版本轴。
- 用户已授权发布全链路；tag创建前必须有精确最终main SHA的全绿Go/SDK CI，之后不移动tag。
- SDK兼容行pending转verified须有实际验证；Windows不代替macOS构建。
- 所有测试资源任务专用，只按完整ID/名称/标签清理，原始材料在.test-output/release-v1.2.0，正式结果仅本变更verification.md。
- 沿用本会话既有沙箱回退方式：在干净主工作区创建短期任务分支隔离，发布过程中同一仓库Git历史用于最终候选及标签核验。
- 根代理维护工件、矩阵、任务和Git阶段提交；工作代理只写分配文件，不提交/推送或派生代理。无共享写入的文档和只读审查可并行。

## Review Focus

- v1.1.0已发布变化不重复算新增破坏性迁移，ADMIN_AUTHORIZATION_MODE不是正式旧变量。
- 角色绑定为空是有效认证后403；不关闭管理认证，不让scope补救，旧Token角色匹配可继续用。
- 旧嵌入宿主RequireRole兼容、新权限优先且不回退；回退旧二进制可能恢复宽授权。
- 最终候选CI必须等于tag目标SHA，候选说明在tag内；补记不是移动tag。
- SDK1.0.0与服务1.2.0分轴；固定本地Git消费和正式远端Go消费分别报告。
