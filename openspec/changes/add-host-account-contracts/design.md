## Context

动机和能力边界见 [proposal](proposal.md)。当前库按渠道、用途、目标保存最新验证码，发码只返回成功，无法区分旧页面的验证轮次；现有每轮计数在重发时重置。用户资料只有单用户查询，注销仅接受到期匿名化回调，缺少注销前置和宿主账号锁保护。现有 PostgreSQL、Redis、HMAC 轮换及冻结迁移约束继续保留。

本 Change 的源码、规格、详细计划与验收都在 accountkit 仓库。宿主的团队规则、业务表、用户引用迁移、发送器装配和 Web 改造不进入此仓库。

## Goals / Non-Goals

**Goals:**
- 用库的完整轮次协议和失败预算替代宿主额外验证码状态。
- 提供批量公开资料与同库业务事务保护，不让宿主耦合私有仓储。
- 离线导入复用现有归一化和密码学，事务最终提交仍由调用者控制。
- 用新不可变版本交付 Go/HTTP/Redis 格式变化，保留原令牌和身份边界。

**Non-Goals:**
- 不改变已完成的 account 默认 schema 决策、JWT/refresh 格式或管理员身份系统。
- 不内置业务所有者判断、产品表、手机号国家码产品策略或客户端 UI。
- 不创建公共用户资料查询或公开导入 HTTP 端点。
- 实施、归档、tag、发布和产品部署分别执行；apply 不自动授权归档、发布或产品部署。

## Decisions

### 1 完整轮次而非响应装饰

发码返回 code_id/expire_time，phone/email 凭证增加 code_id，target 保留以复用归一化与绑定校验。标识由 crypto/rand 生成 128 bit，32 位小写十六进制。轮次绑定渠道、用途、目标摘要；BIND 附加 UserID，REAUTH 附加 UserID/SessionID。验证码 HMAC 包含 code_id，Redis 不保存目标或验证码明文。

仅在 API 返回随机 ID 无法隔离次数；在宿主维护映射会产生第二套认证状态。因此轮次生成、比对、次数和消费均由库的同一次 Lua 操作处理。旧合法格式标识统一 CODE_EXPIRED，不消耗新预算；格式错误为 INVALID_ARGUMENT。

重发替换全部 HMAC 版本的旧轮次，数字相同也不例外。发码与校验按 Lua 的串行顺序处理，不声称可以撤销已经成功的旧轮次验证。

### 2 独立失败预算及配置边界

每轮沿用 CodeMaxAttempts 及默认 5 次；宿主可选择 3 次。默认有效期仍 5 分钟、发送冷却仍 60 秒。新增 CodeFailureLimitPerTarget 默认 10，CodeFailureWindow 默认 15 分钟，对应 CODE_FAILURE_LIMIT_PER_TARGET/CODE_FAILURE_WINDOW，沿用宿主环境前缀。

失败预算按渠道、归一化目标跨用途共享，从首次错误开始，重发或正确码不清除、不续期。合法当前轮次错误才扣预算；猜测 code_id、旧页面流量走接口/IP 限流。达到预算返回 429 TARGET_VERIFY_LIMIT 和剩余 Retry-After。多密钥版本合并实际次数和原截止时间，相同物理键去重，不能在 active 切换时获得新窗口。

选择固定窗口便于用户等待后恢复；持续恶意请求仍可能干扰目标。code_id 不防止验证码钓鱼或短信截获，宿主仍须入口限流和风险控制。

### 3 投递与清理不跨轮次

发送额度先占后投递，仅 provider 返回成功才返回 code_id。失败保留额度和冷却；清理按标识比较后删除，不能误删较新轮次或恢复旧轮次。清理故障依赖原 TTL 失效。发送器 Message 继续只包含用途、验证码、TTL，不要求发送器管理轮次。

响应丢失时首阶段不提供幂等领取标识，客户端在冷却后重新发码。SMTP 接受表示服务商接受提交，不代表最终送达。

### 4 公开 Go 契约

具体签名和测试步骤以 [详细计划](../../../docs/superpowers/plans/2026-10-08-host-account-contracts.md) 为准：

- CodeChallenge 包含 CodeID/ExpireTime；CodeCredential 包含 Channel/Target/CodeID/Code。发码返回结果，登录、绑定、重新认证和换绑接受完整凭证；终端用户接口、可选换绑接口、示例、accountsvc 同步迁移。
- BatchPublicProfiles 批量返回 ID/DisplayName/State，不返回身份字段。未知账号略去，注销账号清空显示名，宿主在业务范围过滤后调用，不创建额外公共 HTTP API。
- BeforeDelete 回调在账号锁及状态确认后、改变状态前调用，共用于 DeleteMe/AdminDeleteUser。ErrDeletionBlocked 对应稳定 DELETION_BLOCKED 原因，宿主业务细节不泄露。其余回调错误为内部错误，不参与现有领域哨兵分类；通过私有不解包错误保留内部诊断而固定 HTTP 500，不新增公共分类类型。调用者不依赖对这些底层错误的 errors.Is/errors.As。
- WithActiveUsers 要求非空账号集合和非 nil 回调，通过库连接池开事务，去重排序锁账号、确认 ACTIVE 后执行宿主回调；库提交/回滚。宿主锁序为账号后业务资源，不自行提交回调事务。空集合不作为通用裸事务入口，宿主空批次直接跳过。
- ImportAccounts 接受调用者事务，只导入 ACTIVE PHONE/EMAIL 锚点账号及无身份、无显示名的 DELETED 墓碑。必需的创建/更新时间应非零并保存原值，不额外强制更新时间晚于创建时间，以容纳历史时钟回退；ACTIVE 不携带删除/匿名化时间。冲突失败，不发码、不建会话、不签令牌。批次记录和业务引用迁移留给调用者。

使用私有 Repo 结构或让宿主直接更新账号状态容易绕过同一不变量，故采用这些范围明确的公开方法。资料读取和导入查询经 sqlc 生成，冻结 SQL 不修改。

### 5 仓库与发布边界

本 Change 是库需求的权威来源；tasks.md 跟踪实际完成，详细计划引用本 Change，不在宿主仓库保留另一份库实施计划。各宿主仅记录依赖能力和已发布版本。库不从宿主配置推导默认次数、schema 或密钥。

## Risks / Trade-offs

- [Go/HTTP/Redis 协议破坏性变化] → 新版本说明全部调用迁移；无 code_id 校验旁路不发布。
- [旧新验证码实例混跑] → 按账号实例停用旧发码和校验，再同步切换调用者；其他独立实例可自行安排升级。
- [HMAC 轮换分裂状态] → 轮次、冷却、额度、失败预算在完整密钥集合下合并并保留原截止时间；真实 Redis 测试必须执行。
- [账号与业务锁死锁] → 库排序账号，宿主先账号后业务资源；并发及回调失败测试覆盖。
- [离线导入部分成功] → 同一调用者事务，错误必须回滚；不自动合并身份，不声称接口本身解决批次幂等。
- [资料泄露] → 仅 Go 批量公开字段，宿主负责调用前的业务范围过滤；不新增任意账号查询端点。

## Migration Plan

1. 在本仓库按详细计划完成测试、实现及兼容文档；不修改已发布 v0.1.0 tag 或冻结迁移。
2. 更新所有 Go 调用者和 accountsvc，完整验证独立构建、真实 PostgreSQL/Redis、轮换、并发及恢复门禁；验收写入本 Change 的 verification.md。
3. 获得发布授权后创建新不可变版本；提供版本号和提交 SHA，由宿主锁定消费。
4. 每个账号实例停止旧验证码写/校验进程并同步更新客户端；旧无标识轮次按 TTL 失效，身份、会话和其他 Redis 数据保留。
5. 正常 HMAC 轮换只在所有程序具备新能力并持有相同完整密钥集合后执行；退役等待身份引用及轮次/冷却/日额度/失败预算均不再需要旧密钥。
6. 回退先停新验证码写/校验并同步调用者，等待新短期状态失效，核对新增错误/审计值和存储兼容；不能只回退二进制或清 Redis 宣称安全恢复。
