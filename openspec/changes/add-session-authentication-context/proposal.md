## Why

当前会话只关联账号，无法按认证身份撤销会话，也无法向客户端说明解绑是否会使当前设备退出；设备描述只有客户端自报的 ID 和名称，缺少浏览器、系统和 App 信息。需要建立可更新的会话认证依据，并通过服务端查询返回一致的会话与客户端描述。

## What Changes

- 为会话记录去重的具体认证身份集合。普通登录记录单个身份，pending 补全登录记录参与此次成功认证的全部身份；成功重新认证原子替换集合并更新 auth_time，刷新及普通新增绑定不改变集合。
- **BREAKING**：解绑成功时，在同一事务中撤销命中该身份及来源未知的该账号未吊销会话，包括当前会话和已到刷新期限但尚未清理的会话。用户已明确选择保守撤销来源未知的旧会话；升级本身不批量退出。
- **BREAKING**：直接 Go 解绑调用与 HTTP 一样复核完整 scope、近期认证和有效当前会话；原来仅提供账号信息的调用方式须迁移到有效 Principal。
- **BREAKING**：换绑继续撤销其他会话；当前会话仅在认证依据已知且不包含被替换身份时保留。新目标的 BIND 证明不隐式替换会话认证依据。
- 新增相对路由 GET /users/me/sessions/current，返回当前有效会话、数据库 auth_time、认证身份摘要（name/kind）、来源是否已知及客户端描述。采用已确认的方案二，JWT 和 refresh 格式不增加来源或设备字段。
- 增加可选客户端类型、系统、浏览器、App、设备类别与型号信息；登录保存初始与最近快照，成功重新认证及新一轮刷新更新最近快照。原设备头、请求体、认证方式、近期认证窗口和刷新宽限规则保持。
- 旧客户端和缺失元数据继续可用；普通业务请求、Authenticate 和内省不增加元数据写入或数据库查询。客户端信息只作描述，不作为可信设备证明。
- 使用 v0.3.0 已发布 0001 之后的真实递增迁移；补齐实例隔离、关联清理、匿名化、审计、兼容说明和真实数据库并发验证。

## Capabilities

### New Capabilities

- `session-authentication-context`：会话认证依据、重新认证替换、身份移除撤销、未知旧会话与当前会话查询。
- `session-client-information`：有界可选客户端信息采集、初始/最近快照、服务端查询与隐私生命周期。

### Modified Capabilities

- `identity-replacement`：当前会话是否保留取决于认证依据，其他会话仍按原规则撤销。
- `embedded-auth-package`：声明身份移除和会话查询的协议升级，同时保留令牌及重新认证契约。
- `versioned-auth-storage`：从已发布 version=1 递增升级，纳入会话认证关联和客户端快照。
- `gateway-integration`：明确新消费者查询路径和可选客户端元信息头的透传边界。

## Impact

- 涉及 user 领域与 query.sql/sqlc、migrations、enum、httpapi/enduser、管理会话 DTO、accountkit 装配、accountsvc 集成、维护/匿名化及对应文档和测试。
- 新查询采用可选 Go 能力接口，不向既有 enduser.Service 强加新方法；请求元数据和会话返回类型增加可选字段。带字段名的 Go 初始化保留用法，位置式初始化的源码兼容风险写入迁移说明。
- Web 适配读取 UA/可用 Client Hints，原生客户端通过可选头补充信息；宿主可覆盖解析。解析不得网络访问，解析依赖需在实施时按许可、维护性、体积和代表性样本选型并记录。
- 生产滚动升级不得让仍执行旧解绑语义的副本与新副本共同承接身份变更；部署与应用回退边界须明确验证。
