# Design

## Context

动机和授权见 [proposal.md](proposal.md)。当前领域通过账号/会话行锁及 subject advisory lock 维护无外键不变量；公开 Repo 故意继承宿主隔离级别。审计查询用物化 CTE 防止稀疏资源查询退化，但后两个分支合并完整 JSON 行且没有分支 LIMIT。`Store.ListByResource` 每页获取全部历史流程证明。

## Goals / Non-Goals

**Goals:** 修复三项已复现问题，建立真实 PostgreSQL 并发和执行计划回归；保持认证、隐私、审计授权和公共宿主接口。

**Non-Goals:** 不更改 schema、0001 或任何历史固定校验；不引入 Redis 锁、专用维护连接、资源关联新表；不处理此次未选定的其他运维建议。

## Decisions

### 内部事务显式 READ COMMITTED

在 Repo 增加包内事务入口，使用 `pgx.TxOptions{IsoLevel: pgx.ReadCommitted}`，领域代码统一通过该入口取得语句级新快照；需要原始 pgx.Tx 的匿名化及 WithActiveUsers 同样显式设置。保留公开 `WithTx` / `WithTxRaw` 及其默认隔离行为；ImportAccounts 接收调用方已经开启的事务，继续由调用方决定隔离级别并遵守停写导入契约。既有直接设置 RC 的隐私写入保留或复用内部入口。保持锁后独立语句复核，不假设取得行锁会刷新 RR 快照。不选择 Redis 锁或 SERIALIZABLE + 全链路重试，因为会增加失败模式或影响验证码与刷新宽限。

### New 无 I/O 验证容量

在 Pool 非空检查之后通过池的配置副本检查 `MaxConns >= 2`，采用既有配置错误风格，不增加公开配置项。`PoolConfig` 继续只解析配置及设置 search_path；用户直接构造池也必须被 `New` 检查。旧单连接生命周期测试更新为支持的最小值，新增专门拒绝测试保留错误场景覆盖。

### 审计窄候选及按页证据

在 SQL 内获得当前/历史归属流程的去重标识，历史证据的 source、namespace、USER 关联和成功 action 谓词保持。数据库内的流程候选允许随相关历史增长；不将全部完整证据及重复 JSON 参数传入 Go。

三个匹配分支分别以 `(occur_time,id)` 排序并取 page_limit 个窄候选，然后按 ID/时间合并去重和取最终页；仅为最终页 ID 获取完整事件。保留必要的规划屏障，使用真实 custom/generic 执行计划验证回表不会引入全表扫描。完整 JSON 不参加无限制 UNION。

从返回页提取去重流程引用，只查询这些流程的当前归属或一份有效历史证明，生成既有 FlowLink。证明查询不受页面 actions/cursor 限制；当前/历史归属同时存在时保持 HTTP 适配器可独立复核。不得让任何 proof 任意关联全部流程或泄漏共享流程其他账号事件。

历史候选仍由 Go 的认证投影规则核验，不在 SQL 复制另一套投影逻辑。优先批量为页内去重流程各取一份候选；遇到同名但投影无效的事件，按唯一游标继续查找，找到有效证据后停止。异常历史可能需要额外读取，这保证原来存在后续有效证明的页面不会因缩减证据而变成 503；普通有效重复证明不全量返回。

非空历史流程规模验证进一步确认：同发生时间的大量事件在第二页加入游标后，规划器可能误估匹配数量，逐流程改走来源时间索引并重复扫描。因此 flow 匹配子查询先按 source、精确流程引用和授权条件取得资源候选并设置规划屏障，动作和游标过滤在屏障之外执行，再去重/取页。测试分别控制真实 Store 连接的计划模式与 JIT，并核对第二页计划，避免把 EXPLAIN 连接的设置误当作 Store 的设置。

## Risks / Trade-offs

- RC 单独不能保证跨行不变量 → 保留并核对所有既有锁、锁序、事务内复核及唯一索引。
- 新容量要求影响显式 MaxConns=1 宿主 → README/兼容说明写明至少 2；默认 pgx 不受影响。
- Top-N 分支或证据缩减可能改变授权/分页 → 测试多分支重复、同时间、空页、动作过滤、已删除流程、共享流程和跨 source/namespace。
- 窄候选仍可能扫描大量相关历史 → 报告真实计划、内存/临时文件和扫描量，不把减少完整行物化夸大为常数时间。
- 没有新表/索引 → 保持部署简单，若未来需要完全有界历史查找，另行设计资源关联索引。

## Migration Plan

升级前将显式单连接池调整到至少 2。无需数据库迁移或数据转换，公开 Repo 调用方无需修改。部署时按既有基线预检运行；回退代码不会引入数据格式变化，但会恢复本次修复前的运行风险。
