# Spec Delta

## ADDED Requirements

### Requirement: 本地审计分页限制完整历史处理

本地审计 Reader SHALL 在最终分页之前限制各匹配分支参与完整记录合并的数量，避免仅为返回一页而物化和去重资源全部历史事件的完整 JSON 内容。返回顺序、动作过滤、游标、来源和命名空间隔离 SHALL 保持。资源匹配可以扫描必要的索引候选，不承诺没有新增索引的条件下总扫描量恒定。

#### Scenario: 单资源密集历史
- **WHEN** 单资源有十万条审计事件且请求 51 条
- **THEN** 最终完整事件读取最多 51 条，分支合并采用有界候选，不对十万条完整事件做 UNION 排序

#### Scenario: 稀疏资源及通用计划
- **WHEN** 大量不相关事件中仅少量属于请求资源，数据库采用 custom 或 generic plan
- **THEN** 资源匹配保持索引支持，最终页回表不退化为逐页扫描全部事件完整内容

#### Scenario: 多分支重叠和相同发生时间
- **WHEN** 同一事件同时匹配 actor、targets 或 related_resources，且存在相同 occur_time
- **THEN** 事件只返回一次，按 occur_time 和 id 翻页不重不漏，动作过滤在取页前生效

### Requirement: 流程归属证据按页返回

本地 Reader SHALL 在数据库内解析历史流程归属，仅向调用方返回当前页关联所需的去重流程链接和有效证据，不因每次分页传输全部历史证据。有效归属仍来自当前流程或既有认可的成功证明事件，不能通过截断证据查询造成历史遗漏。已有公开 Reader、Page 和 FlowLink 类型 SHALL 保持。

#### Scenario: 大量重复证明
- **WHEN** 某账号同一流程有多次成功证明和完成事件
- **THEN** 一页中的相同流程链接去重，不反复将全部证明 JSON 载入 Go 或作为重复 SQL 参数传回数据库

#### Scenario: 证据不在当前时间或动作范围
- **WHEN** 当前页查询早期流程事件，其归属证据发生在游标之后或属于其他 action
- **THEN** 仍使用有效证据授权该流程事件，不将页面过滤错误地应用于归属证明

#### Scenario: 多账号共享流程
- **WHEN** 账号 A 和 B 共同参与同一流程
- **THEN** A 的页面可包含关联 A 和尚无明确账号归属的早期事件，不包含仅关联 B 的专属事件
