# Proposal

## Why

当前仓库的稳定协议、错误原因、审计资源类型和配置字段在多处以字符串字面量维护，部分已有常量仍被绕过，容易在后续修改中出现命名或分支漂移。全仓盘点得到78组候选，需要按语义归属收敛，并以现有行为与独立协议断言约束重构，避免把重复文字机械替换成新的公共API。

## What Changes

- 覆盖Go库、accountsvc、Flutter/TS SDK、示例、SDK测试装配、验证和发布工具；将78组候选的值、位置、归属和实施任务保存为本变更内的可追踪清单，不依赖被忽略的临时报告。
- 优先复用已有常量、领域方法和标准库/当前依赖定义；按协议或能力拥有者补充HTTP/OAuth/JOSE标识、HTTP reason、认证审计原因、验证码状态、SMTP模式和提供方协议定义。
- 将资源名、挑战响应、缓存策略、Redis键与指纹等直接相关的重复构造收敛为小型帮助函数；已有解析器仅共享字段、关键字和描述数据，不重写语法、识别算法或规则集合。
- 各SDK内部整理scope、kind、流程错误、请求元数据、匿名端点及重复wire字段；工具与fixture独立整理测试元数据、临时资源前缀、SDK描述及恢复阶段，保持源码分发与独立安装边界。
- 保持所有既有字符串原值、HTTP状态/响应头/错误顺序、审计归属与隐私语义、实例隔离、持久化及密码学字节格式、环境变量及公开Go/SDK API兼容。不同语义的同值字符串分别定义，既有公开符号保留。
- 分模块执行行为回归与独立审查，步骤通过后本地提交；测试保留必要的独立预期值，不能让实现常量与断言同错同过。逐组记录处理结果或有证据的保留理由，不以字符串数量下降作为完成标准。

## Capabilities

### New Capabilities

无。此次是保持现有行为的实现重构，不新增业务功能、配置选项或协议能力。

### Modified Capabilities

无行为需求变更。`.openspec.yaml`显式设置`skip_specs: true`，不创建增量specs或修改主规格。实施如发现必须改变既有合法输入、错误分类、格式、公共签名或算法，先停止该部分并另行设计，不以常量整理名义吸收行为变化。

## Impact

- Go重点：`httpapi/`、`internal/accountsvc/`、`tokens/`、`user/`、`audit/`、`session/`、`maintenance/`、`observability/`、根配置及迁移装配；新增共享定义只放在有清晰职责、无认证业务依赖的内部叶子模块，避免循环导入与全仓constants包。
- 客户端及工具：`sdks/accountkit-flutter`、`sdks/accountkit-admin-ts`、`sdks/testsupport`、`scripts/`、`examples/`及发布检查工具。SDK源码不导入父仓库定义；fixture控制协议不进入SDK生产依赖。
- 关联的现有规格包括HTTP凭据解析、通用审计、验证码、第三方登录、迁移安全、SDK分发与指标；以主规格和已合入但未归档的`configure-admin-permissions`增量规格共同校验兼容性，不改写旧变更。
- 不修改sqlc生成代码、生产SQL、冻结迁移/哈希、锁文件或现有持久化值；不统一不同身份面的授权、不同IdP的主体空间或不同语义的错误。普通一次性文案、JSON tag、模板正文和独立测试预期不机械常量化。
- 本次ff只准备工件，不实施、合并、推送、归档、打tag或发布。实施结果、审查及未验证项统一记录在本变更`verification.md`。
