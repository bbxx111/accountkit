## MODIFIED Requirements

### Requirement: 已发布迁移不可改写
发布过程 SHALL 验证所有可达正式标签及完整历史，拒绝已发布迁移被修改、删除或重编号；后续结构修改 SHALL 使用递增版本。此前初始整合以及本次用户明确要求“直接修改原始数据库定义、不新增迁移”的通用审计调整 SHALL 是限定例外：仅当前未发布的 0001 定义及其固定校验更新，固定源快照、v0.1.0/v0.2.0 的历史 SQL 和精确发布提交保持；不得移动标签、添加忽略历史或跳过校验的开关。本次调整不表示可以自动重写已有数据库。

#### Scenario: 修改历史 SQL
- **WHEN** 发布检查发现对应基线下的已发布迁移内容变化或消失
- **THEN** 发布检查失败并指出文件；不得通过覆盖源快照或新增标签绕过检查

#### Scenario: 固定历史发布
- **WHEN** 检查可达的 v0.1.0 或 v0.2.0
- **THEN** 同时核对固定提交与原始 SQL；被移动的同名标签不能获得旧基线例外

#### Scenario: 用户授权调整原始定义
- **WHEN** 本次通用审计按明确用户指令直接调整 0001
- **THEN** 当前固定校验同步更新、空库初始化仍为版本 1；不新增生产迁移，旧结构明确拒绝，历史标签及源快照不变

#### Scenario: 整合后发布
- **WHEN** 新正式标签或合并分支新增迁移
- **THEN** 核对当前初始基线与该代全部已发布增量，HEAD 标签不能掩盖篡改，新增版本必须递增
