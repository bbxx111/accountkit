## 1. 发布准备

- [x] 1.1 盘点 v0.2.0 之后的最终变更及相关规格，确认下一版本为 v0.3.0。
- [x] 1.2 编写发布说明及版本门禁，明确旧库、登录返回、审计 API/游标、可兼容别名与集成方责任。
- [x] 1.3 对精确代码快照执行生成检查、完整库与服务门禁及恢复演练，保存结果和原始日志。
- [x] 1.4 完成发布说明独立审查、链接/差异及 OpenSpec 严格检查，将证据及未完成的正式发布步骤写入 verification.md。

上述任务仅覆盖准备工作。用户随后明确要求继续提交、合并、推送及正式发布，执行以下阶段；归档仍作为单独明确步骤。

## 2. 正式发布

- [ ] 2.1 提交准备材料，以独立 merge commit 合入 develop 和 main，推送并记录最终 main 候选 SHA。
- [ ] 2.2 核对最终候选在线 CI 全部通过，确认生成、完整库/服务、race、必需测试及恢复步骤成功。
- [ ] 2.3 创建并推送固定 v0.3.0 tag，核验远端指向，并使用本版本说明发布 GitHub Release。
- [ ] 2.4 从远端以无 replace 的独立宿主消费 v0.3.0，验证根门面、直接 enduser、新登录返回、审计及指标装配，补记发布状态和证据。
