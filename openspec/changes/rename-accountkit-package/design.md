## Context

动机见 proposal.md。根包及外部测试使用旧包名，维护锁也包含同一历史字符串；冻结 manifest 记录历史文件名。这些位置需要按用途处理。

## Goals / Non-Goals

**Goals:** 统一公共命名与文档，同时保持运行契约。
**Non-Goals:** 本轮不实现 accountsvc 运行时或此前探索的认证增强，不更改 module、SQL、环境变量、Auth 类型和 HTTP 协议。

## Decisions

1. 根包改名，门面及对应测试文件改为 accountkit*.go；外部测试和示例使用无别名导入。保留 Auth 类型，避免扩大 API 变更。
2. 同步诊断消息与可修改注释。维护锁中的历史标识保留并补充说明；改变该值会使新旧进程不再互斥，不能机械替换。
3. 文档覆盖 README、AGENTS、操作手册、基线说明、现有 OpenSpec 工件；以冻结基线和宿主契约重述，不删除验证要求。原始 manifest 和 SQL 不修改，历史 change 标识保持稳定。
4. 现有变更的历史决定在文中标注由本次明确重命名要求取代，避免将旧任务伪装为执行过新命名。
5. accountsvc 是可选官方宿主，其装配依赖方向指向本库；库不得依赖 accountsvc。运行时实现单独规划。

## Risks / Trade-offs

- [无别名导入的调用方编译失败] → 迁移说明要求改用 accountkit 标识符，或显式保留 authserver 导入别名。
- [全局替换破坏历史锁和校验基线] → 定向修改；用历史迁移检查和差异审查核验。
- [历史验证被误读为当前通过] → 保留记录日期，交付时单独列出本轮实际检查。

## Migration Plan

保持 module 路径，更新调用方包标识符并重新构建。不需要 SQL 迁移；若回退代码，调用方相应恢复导入别名，运行数据不变。
