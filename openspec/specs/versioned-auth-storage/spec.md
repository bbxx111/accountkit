# versioned-auth-storage Specification

## Purpose

使账号认证包自行携带完整数据库结构与迁移版本，同时与宿主业务迁移链分离，支持指定 PostgreSQL schema 的首次安装、重复执行及当前基线内的增量升级，并明确旧基线拒绝和历史数据、凭证格式的验证边界。

## Requirements

### Requirement: 包内数据库定义

包 SHALL 随发布产物携带用户、身份、会话、审计、短期登录补全流程及新增会话认证身份关联、客户端快照的定义与迁移，宿主不需要复制 SQL；目标 schema SHALL 可配置，迁移记录与新增表 SHALL 位于对应实例 schema。v0.3.0 已发布的 0001、固定校验、源快照和正式标签 SHALL 保持原样；后续真实结构变更 SHALL 从 0002 递增，禁止借用此前未发布阶段的有限授权改写历史。新增引用 SHALL 不采用外键或级联删除，由领域事务及清理路径保证一致性。

#### Scenario: 空数据库安装
- **WHEN** 对合法且尚不存在的目标 schema 执行迁移
- **THEN** 按顺序执行已发布0001及新增真实递增迁移，保留 sign_in_completion_flow 名称并建立会话认证关联与客户端快照，version 达到发布目标且 dirty=false，不在 public 或其他业务 schema 新建认证表

#### Scenario: 非法 schema
- **WHEN** schema 名不符合 ^[a-z][a-z0-9_]{0,62}$
- **THEN** 返回配置错误，不执行由该名称组成的数据库变更

#### Scenario: 已发布初始定义保持
- **WHEN** 检查新版本的0001与v0.3.0已发布SQL
- **THEN** 字节及固定哈希保持，新表/字段只由递增迁移加入；索引和约束名称遵守前缀及63字节上限

#### Scenario: 直接定义仅调整名称
- **WHEN** 将当前初始 catalog 与改名前定义按授权名称映射后对比
- **THEN** 列、主键、CHECK、索引定义和表数量保持，标识符长度不超过 PostgreSQL 上限，当前固定校验与实际字节一致；该历史对照仅针对冻结的0001，不将后续递增迁移混入初始定义或授权重写历史

### Requirement: 版本化重复执行
迁移 SHALL 仅应用未成功执行的版本。重复调用成功迁移 SHALL 不重建表或破坏已有数据；这项保证不表示每条原始 SQL 可脱离迁移器重复执行。

#### Scenario: 连续迁移
- **WHEN** 对已完成版本的非空数据库再次迁移
- **THEN** 成功返回且版本、账号、身份和会话保持不变

### Requirement: 宿主迁移链隔离
认证迁移 SHALL 不修改宿主业务迁移记录，也不影响同库其他认证 schema。

#### Scenario: 两个独立版本记录
- **WHEN** 同库两个认证 schema 和业务 schema 均已存在
- **THEN** 对其中一个认证 schema 执行迁移，不改变另外两个 schema 的结构、数据与迁移版本

### Requirement: 整合基线的兼容边界
迁移 SHALL 接受具有新流程表的完整当前初始结构及其正常递增版本，拒绝旧流程表名、旧审计列结构和已撤回旧增量结构，不因版本数字相同而返回虚假的安装成功。拒绝 SHALL 保留表、数据和版本标记；dirty SHALL 继续按原规则优先阻断。预检 SHALL 要求完整 sign_in_completion_flow 且不存在 identity_flow，继续要求十列 UUID 审计结构，并按迁移版本核对新增会话结构；不要求旧 flow_id 专属列，不自动重放初始 SQL、重命名、重建、清库或转换旧库。

#### Scenario: 旧初始库版本同为一
- **WHEN** 旧 version=1 数据库仍使用 identity_flow、缺少完整流程结构或仍具有旧审计列
- **THEN** 返回明确不兼容错误，旧记录、结构与版本保持，不自动重放 0001

#### Scenario: 旧开发增量库
- **WHEN** 连接非本次正式递增链生成的旧 version=2 数据库，包括此前已撤回重命名方案产生的新表名 v2
- **THEN** 返回明确不兼容错误，不降版本或清库，也不自动重放 0001

#### Scenario: 双表并存
- **WHEN** 当前实例同时存在新旧流程表
- **THEN** 返回明确不兼容错误，数据、结构和版本保持

#### Scenario: 新基线重复执行
- **WHEN** 当前发布目标的初始结构及全部递增迁移已经安装且包含数据，再次执行迁移
- **THEN** 成功且结构、版本和数据不变，不重新分配资源 ID；不影响其他 schema

#### Scenario: 历史数据格式验证
- **WHEN** 将固定历史合成账号、身份密文和令牌直接装载到当前初始结构，并明确映射历史审计合成记录
- **THEN** 原账号等非审计 ID、密文解密、摘要查找及有效 access/refresh 仍可使用，审计映射保留旧 ID 可追溯关系；不把该验证称为旧库原地升级，不修改固定旧快照

#### Scenario: 正式会话结构递增升级
- **WHEN** v0.3.0完整非空version=1实例应用新增会话迁移
- **THEN** 原用户、身份、会话和凭据保持，来源未知且描述缺失，不自动退出；新目标版本的重复Up成功且不重建关联

#### Scenario: 版本同号但结构不同
- **WHEN** 对比本次合法version=2与历史已撤回旧version=2实例
- **THEN** 根据完整结构区分并只接受合法迁移链，旧结构拒绝且数据/版本不变，不添加Force或跳过历史检查开关
